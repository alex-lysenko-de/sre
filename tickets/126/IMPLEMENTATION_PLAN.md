# Тикет 126: Архитектурный план

> Роль: Software Architect. Документ описывает архитектуру решения по
> `tickets/126/126.txt` — код не пишется и не меняется в рамках этого
> документа.

## Цель

Семь независимых UI/UX-доработок навигации и модуля сканирования,
выявленных на практике использования:

1. Кнопка-логотип в навбаре не читается как кнопка перехода в главное
   меню.
2. Кнопка "Ich fahre heute mit!" сдвигает навбар — переносится на
   Willkommen.
3. Кнопки пересчёта видны пользователям, не отметившимся на сегодня.
4. Выбор камеры сканера занимает место в рабочем интерфейсе — выносится
   в отдельный пункт меню "Scanner".
5. Встроенная панель сканера в Kopfzählung (тикет 123) схлопывается
   целиком по простою — должна выключаться только камера, область
   остаётся на месте.
6. Кнопка "Reset" в режимах сканирования бесполезна — заменяется на
   "Close".
7. Несвязанный бейдж должен предлагать привязку вместо авто-закрытия
   сообщения.

Все семь пунктов — независимые изменения без общей сквозной фичи; общий
знаменатель — все они трогают либо навбар/`MainView.vue`, либо
`Scanner.vue` и его потребителей. Ни один пункт не требует изменений
БД/API.

## Анализ текущей архитектуры

- **Навбар (`App.vue`)**: кнопка-логотип — `router-link` с текстом
  `🌳 SRE` (:22-24). Кнопка "Ich fahre heute mit!" — `:15-19`,
  единственная точка входа в `DailyCheckInModal` во всём проекте
  (проверено грепом `showCheckInModal|DailyCheckInModal` — других
  вхождений нет). Модалка и её состояние (`showCheckInModal`,
  `onCheckInCompleted`, `onCheckInError`) сейчас живут в `App.vue`,
  смонтированы всегда (не привязаны к конкретному роуту).
- **`isCheckInRequired`** — геттер `stores/user.js:29`:
  `!!state.userInfo.id && !state.userInfo.isPresentToday`. Уже
  используется в `App.vue` для скрытия индикатора автобуса (:39) —
  переиспользуется без изменений для новых условий на `MainView.vue`.
- **`MainView.vue`** — кнопки пересчёта (Bus zählen :92-108,
  Gruppen-Appell :111-127, Freie Meldung :130-143) сейчас видны при
  простом `v-if="isAuthenticated"`, без учёта `isCheckInRequired`.
- **Камера в `Scanner.vue`** (:34-65, :90-286) — выбор камеры полностью
  инкапсулирован внутри компонента: `cameraList`, `currentCameraId`,
  `showCameraSelector`, `chooseCamera()`, персистентность через
  `localStorage['scanner_preferred_camera_id']` (`CAMERA_STORAGE_KEY`).
  Длительности показа результата — константы `CONFIRMATION_DURATION_MS`
  (:131-134, success 1600мс/error 3000мс), нигде не настраиваемые.
  `Scanner.vue` — общий компонент без знания о вызывающем режиме (см.
  собственный комментарий в шапке файла), используется во всех четырёх
  потребителях: `ScannerBusView`/`ScannerGroupView`/`ScannerCheckinView`
  (полноэкранные) и встроенная панель `HeadcountView.vue` (тикет 123).
- **Панель сканера в `HeadcountView.vue`** (тикет 123) — управляется
  `useGroupScanSession.js`: `isOpen` включает/выключает **весь**
  `<Scanner>` через `v-if="groupScanSession.isOpen.value"`
  (`HeadcountView.vue:56`), кнопка "Scan" видна только при
  `!isOpen` (:40). `scheduleAutoClose()`/`AUTO_CLOSE_IDLE_MS=5000`
  (`useGroupScanSession.js:15,61-64`) вызывает `closePanel()` через 5с
  простоя после последнего успешного скана — который сейчас делает
  `isOpen.value = false` + фоновая отправка (`submitInBackground`).
  Полное размонтирование `<Scanner>` останавливает камеру через её
  собственный `onBeforeUnmount`/`stopScanning()`.
- **Кнопка "Reset"** — идентична в трёх полноэкранных режимах
  (`ScannerBusView.vue:27-29`, `ScannerGroupView.vue:57-59`,
  `ScannerCheckinView.vue:29-31`): `@click="handleReset"` →
  `scanPacket.resetPacket()` + очистка локального списка.
  **Уточнение к 126.txt**: `handleReset` вызывается не только с кнопки —
  все три `handleSend()` вызывают его повторно после успешной отправки,
  чтобы очистить экран для следующего раунда сканирования (например
  `ScannerBusView.vue:99`). Удалять саму функцию/логику сброса нельзя —
  убирается только пользовательская кнопка "Reset"; внутренний вызов
  после `handleSend()` остаётся как есть (возможно, под новым именем,
  не связанным больше с текстом "Reset").
- **Результат `not-found`** (`Scanner.vue:358-361`, `bandId` при
  нём) — все три `handleResolved` полноэкранных режимов возвращают
  `undefined` для любого статуса кроме `found`, то есть полностью
  делегируют показ в `Scanner.vue`: `defaultDisplayFor()` (:298) даёт
  title "Kein Kind mit dem Verband verbunden", показывается на
  `CONFIRMATION_DURATION_MS.error` (3000мс) и автоматически
  возобновляет сканирование. `Scanner.vue` сейчас не имеет зависимости
  от `vue-router` — не импортирует и не использует его.
- **Существующий маршрут привязки бейджа** — `/armband/:id`
  (`router/index.js:59-64`, `name: 'Armband'`, `requiresAuth: true`,
  без `requiresAdmin`) → `ArmbandView.vue`. Уже реализован и рабочий
  (в отличие от `/armband-connect/:id` → `ArmbandConnectView.vue`,
  который является нереализованной заглушкой-TODO — не путать и не
  использовать). Это тот же экран, на который сегодня ведёт редирект
  `?id=<bandId>` в конце `router.beforeEach` (:269-274). Важное
  ограничение: `ArmbandView.vue` при непривязанном браслете предлагает
  выбор только среди детей **группы текущего пользователя**
  (`loadChildren()` → `armband.getChildrenByGroup(currentGroupId)`,
  :168-186) — это существующее ограничение, не устраняется в рамках
  126; для режима "Freie Meldung" (CHECKIN, без фильтра по группе) это
  означает, что найденный ребёнок для привязки может оказаться не в
  списке, если он не из группы сканирующего — см. «Риски».
- **`useConfigStore` (`stores/config.js`)** — хранит **общую**,
  редактируемую администраторами конфигурацию лагеря (таблица `config`
  в Supabase, кэш в `localStorage` с TTL). Настройки камеры — это
  персональная настройка **устройства**, не организации; переиспользовать
  `useConfigStore`/таблицу `config` для них architecturally неверно
  (у каждого воспитателя своя предпочтительная камера на своём
  телефоне) — нужен отдельный локальный механизм, аналогичный уже
  существующему `CAMERA_STORAGE_KEY` в `Scanner.vue`, только вынесенный
  наружу и расширенный на длительности сообщений.
- **`useArmband.js`** — `getBraceletStatus`/`assignBraceletToChild` уже
  используются `ArmbandView.vue` и не нуждаются в изменениях.

## Изменения существующих компонентов

### `App.vue`

- Кнопка-логотип (:22-24): текст/иконка меняются на явно узнаваемые —
  иконка `['fas','home']` (уже используется в проекте,
  `MainView.vue:6`) + подпись `Home`/`Main`/`Haupt` (конкретный текст —
  на усмотрение реализации, ключевое требование — не `🌳 SRE`).
- Блок :15-19 (кнопка "Ich fahre heute mit!"), `<DailyCheckInModal>`
  (:4-9), `showCheckInModal`/`onCheckInCompleted`/`onCheckInError` —
  удаляются из `App.vue` целиком и переносятся в `MainView.vue` (см.
  ниже). Единственная зависимость, которую нужно сохранить в новом
  месте — вызов `userStore.loadUser(true)` при завершении чек-ина
  (сейчас `onCheckInCompleted`, `App.vue:331-335`).
- Новый пункт меню в `<ul class="navbar-nav">` (:64-96), без
  `requiresAdmin` (доступен всем аутентифицированным пользователям, как
  `/info`):
  ```html
  <li class="nav-item">
    <router-link to="/scanner/settings" class="nav-link text-white" @click="closeMenu">
      📷 Scanner
    </router-link>
  </li>
  ```

### `MainView.vue`

- Добавляется кнопка "Ich fahre heute mit!" в общую сетку `d-grid
  gap-3` (:24-177), видимая при `isAuthenticated && isCheckInRequired`
  (новый локальный computed от `userStore.isCheckInRequired`),
  стилистически как остальные кнопки меню (`btn-lg`, не обязательно
  `btn-warning fw-bold` — фактический стиль на усмотрение реализации).
- Импортируется `DailyCheckInModalView.vue`, добавляется локальный
  `showCheckInModal`, обработчики `onCheckInCompleted`
  (`userStore.loadUser(true)`) и `onCheckInError` — перенесены из
  `App.vue` без изменения логики.
- К `v-if` кнопок Bus zählen (:92), Gruppen-Appell (:111), Freie
  Meldung (:130) добавляется `&& !userStore.isCheckInRequired`.
  Кнопки "Zu meiner Gruppe"/"Kopfzählung" (:27-56) не меняются — не
  относятся к пересчёту сегодняшнего дня (см. 126.txt).

### `Scanner.vue`

- Убирается `.proto-scanner-controls` целиком: кнопка выбора камеры,
  `showCameraSelector`, список `proto-camera-list`, функция
  `chooseCamera()` в её нынешнем виде.
- Логика камеры (`cameraList`, текущий `currentCameraId`,
  чтение/запись `localStorage`) переносится в новый composable
  `useScannerSettings.js` (см. «Новые компоненты»); `Scanner.vue`
  вызывает его при инициализации вместо владения этим состоянием
  напрямую. `initScanner()` теперь читает `preferredCameraId` из
  composable вместо `localStorage.getItem(CAMERA_STORAGE_KEY)`
  напрямую; список камер (`Html5Qrcode.getCameras()`) по-прежнему
  запрашивается при инициализации (нужен и для старта, и на случай
  первого захода на экран настроек) — вызов делегируется composable
  (`loadCameraList()`), результат кэшируется в его реактивном
  состоянии, чтобы `ScannerSettingsView.vue` мог им переиспользоваться
  без повторного запроса разрешений сразу же.
- Длительности показа результата (`CONFIRMATION_DURATION_MS`) читаются
  из того же composable (`successDurationMs`/`errorDurationMs`) вместо
  захардкоженных констант; значения по умолчанию (1600/3000мс) переносятся
  в composable как дефолты настроек.
- **Новый проп `autoStart`** (default `true`): при `false` компонент не
  вызывает `initScanner()` в `onMounted`, а сразу показывает новое
  состояние "камера выключена" (см. ниже). Нужен для встраивания в
  `HeadcountView.vue` (пункт 5).
- **Новое состояние "камера выключена"**: когда
  `!scannerActive && !isTransitioning && !confirmation.show` — то есть
  после явной остановки (см. `stop()` ниже) или при `autoStart=false`
  до первого запуска — область сканера показывает кнопку "Scan" на всю
  область вместо потока с камеры. По клику вызывается тот же внутренний
  метод, что запускает камеру при обычной инициализации (переиспользует
  сохранённый `preferredCameraId`, не повторяет запрос списка камер).
  Это не относится к штатной микропаузе `html5QrCode.pause(true)`
  внутри `onScanSuccess` (:323, :387) — там `scannerActive` не меняется,
  новое состояние не показывается.
- **`defineExpose`** (:441) дополняется методом `start()` (публичный
  вход в тот же internal camera-start, что и кнопка "Scan" из
  предыдущего пункта) — наряду с уже существующими `stop`/`showMessage`.
  Вызывающая сторона (`useGroupScanSession.js`) получает возможность
  включать/выключать камеру, не размонтируя компонент.
- **Новый необязательный проп `onBindRequested(bandId)`**: если передан
  — статус `not-found` показывает не автозакрывающийся стандартный
  экран, а персистентный экран с двумя кнопками "Cancel"/"Привязать
  бейдж" (текст на усмотрение реализации, суть — по-русски "Cancel" и
  "Привязать бейдж" из 126.txt). "Cancel" скрывает экран и возобновляет
  сканирование (тот же путь очистки, что сейчас в конце
  `onScanSuccess`). "Привязать бейдж" вызывает `props.onBindRequested(bandId)`
  и **не** возобновляет сканирование сам — ожидается, что вызывающая
  сторона либо демонтирует `Scanner.vue` (переход на другой роут —
  `onBeforeUnmount` остановит камеру автоматически), либо явно вызовет
  `stop()`. Если проп не передан — поведение `not-found` не меняется
  (текущий автозакрывающийся экран, как сегодня); так закрывается
  вопрос из 126.txt о встроенной панели `HeadcountView.vue` — она этот
  проп не передаёт (см. ниже), решение принято на этом этапе, а не
  оставлено открытым.
- `Scanner.vue` по-прежнему не импортирует `vue-router` напрямую —
  переход на `/armband/:id` остаётся ответственностью
  вызывающего экрана через `onBindRequested`, а не самого `Scanner.vue`
  (сохраняет текущий принцип компонента: "не знает о режимах, отдаёт
  результат наверх через колбэки", см. шапку файла).

### `ScannerBusView.vue` / `ScannerGroupView.vue` / `ScannerCheckinView.vue`

Одинаковое изменение во всех трёх:

- Кнопка "Reset" → "Close": `@click="handleClose"`, где
  `handleClose = () => router.push('/main')` (явный переход на
  Willkommen — не `router.back()`, так как эти экраны могут быть
  открыты не только из `MainView.vue`, чтобы поведение не зависело от
  истории браузера). Отправка ничего не отправляет, побочных действий
  нет.
- Существующая `handleReset()` (сброс `scanPacket`+локального списка)
  **не удаляется** — остаётся как внутренний helper, вызываемый из
  `handleSend()` после успешной отправки (как сегодня); просто больше
  не привязан ни к какой видимой кнопке напрямую (можно переименовать
  в `clearScanState()`, чтобы не путать с удалённой кнопкой — на
  усмотрение реализации).
- Новый обработчик, передаваемый в `Scanner` как `:on-bind-requested`:
  ```js
  const onBindRequested = (bandId) => {
    handleReset() // очистить накопленный пакет/список без отправки
    router.push({ name: 'Armband', params: { id: bandId } })
  }
  ```
  Именно этот путь реализует требование 126.txt "перед переходом
  текущая сессия сканирования завершается, а список очищается".

### `HeadcountView.vue` + `useGroupScanSession.js`

- `HeadcountView.vue:56` — `<div class="kz-scanner-panel">` рендерится
  всегда (без `v-if="isOpen"`); кнопка "Scan" на :40 удаляется как
  отдельный элемент — её заменяет встроенная в `Scanner.vue` кнопка
  "Scan" из нового состояния "камера выключена" (см. выше).
  `<Scanner>` получает `:auto-start="false"` и **не** получает
  `:on-bind-requested` (сохраняется текущее поведение `not-found` —
  решение по открытому вопросу 126.txt, см. выше).
- `useGroupScanSession(groupIdRef, childrenRef)` получает третий
  параметр `scannerRef` (заполняется `HeadcountView.vue` через
  `ref="scannerRef"` на `<Scanner>`, по аналогии с
  `ScannerBusView.vue` и остальными полноэкранными режимами).
- `isOpen` переосмысливается как "камера сейчас активна" — по сути не
  требует переименования переменной (значение то же самое: включена ли
  съёмка), но её роль меняется: теперь используется только для того,
  чтобы решить, показывать ли что-либо снаружи `Scanner.vue` (например,
  ничего — вся кнопка "Scan"/поток теперь внутри самого компонента), а
  не для монтирования/размонтирования.
- `openPanel()` (:66-70) переименовывается в вызов `scannerRef.value?.start()`
  вместо `isOpen.value = true` — либо убирается вовсе, если открытие
  теперь целиком происходит по клику на встроенную кнопку "Scan"
  внутри `Scanner.vue` (в этом случае `isOpen` синхронизируется через
  колбэк/событие от `Scanner.vue` — конкретный механизм на усмотрение
  реализации, например через `@camera-started`/`@camera-stopped` emit
  вместо чтения внутреннего состояния).
- `closePanel()` (:55-59) — вместо `isOpen.value = false` вызывает
  `scannerRef.value?.stop()`; `submitInBackground()` остаётся как есть.
- `scheduleAutoClose`/`AUTO_CLOSE_IDLE_MS` (:15,61-64) — таймер и его
  сброс при каждом успешном скане (`handleResolved`, :93,99) не меняются
  по таймингу, меняется только то, что происходит по истечении (останов
  камеры вместо размонтирования панели).

## Новые компоненты

### `src/composables/useScannerSettings.js`

Обычный composable (не Pinia-стор — состояние чисто локальное,
устройство-специфичное, без Supabase-слоя; по объёму и характеру ближе
к прямому использованию `localStorage`, как это уже делает
`Scanner.vue` сегодня, просто вынесенное в переиспользуемое место,
т.к. теперь у настроек два потребителя — `Scanner.vue` и
`ScannerSettingsView.vue`):

- Реактивное состояние: `cameraList`, `preferredCameraId` (`null` =
  автоматический режим), `successDurationMs`, `errorDurationMs`.
- `loadCameraList()` — обёртка над `Html5Qrcode.getCameras()`
  (перенесена из `Scanner.vue:181,267`), пишет в `cameraList`.
- `setPreferredCameraId(id)` / `setSuccessDurationMs(ms)` /
  `setErrorDurationMs(ms)` — обновляют реактивное состояние и
  синхронно пишут в `localStorage` под одним новым ключом (например,
  `scanner_settings`, единый JSON-объект вместо нескольких отдельных
  ключей).
- **Миграция**: при первом чтении, если новый ключ отсутствует, но
  существует старый `scanner_preferred_camera_id` (уже есть на
  устройствах, где камера была выбрана до этого тикета) — его значение
  переносится в `preferredCameraId` нового формата один раз, старый
  ключ можно оставить или удалить (не критично).
- Не содержит UI и не знает о `Scanner.vue`/`ScannerSettingsView.vue`
  — оба потребителя импортируют одни и те же реактивные ref'ы (модуль
  создаёт **один** shared instance состояния — по аналогии с
  `src/modules/storage.js`, а не новый independent state при каждом
  вызове — иначе `Scanner.vue` и `ScannerSettingsView.vue` не увидят
  изменений друг друга без reload).

### `src/views/ScannerSettingsView.vue`

- Список камер (из `useScannerSettings.cameraList`, с опцией
  "Автоматический выбор" как сегодня в `Scanner.vue`'s
  `proto-camera-list`, просто перенесённый на отдельный экран) —
  выбор вызывает `setPreferredCameraId`.
- Поля/слайдеры для `successDurationMs`/`errorDurationMs` (в разумных
  пределах, например 500–5000мс — конкретные ограничения на усмотрение
  реализации).
- Вызывает `loadCameraList()` при монтировании (аналог того, что
  сегодня `Scanner.vue` делает в `initScanner()`), чтобы список был
  актуален даже если пользователь ещё ни разу не сканировал на этом
  устройстве.
- Не содержит собственной логики сканирования — не встраивает
  `Scanner.vue`.

## Риски

- **`Scanner.vue` берёт на себя много новой ответственности за один
  тикет**: управляемый `autoStart`/`start()`/`stop()` жизненный цикл,
  новая персистентная ветка confirmation-экрана с кнопками, чтение
  внешних настроек — компонент растёт в размере и в количестве
  состояний. Остаётся одним файлом сознательно (это по-прежнему "один
  переиспользуемый примитив сканирования"), но это стоит держать в
  голове при код-ревью.
- **Рефакторинг `useGroupScanSession.js`/`HeadcountView.vue` (тикет
  123)** — меняет уже написанный, но не проверенный на реальном
  устройстве код (`tickets/dashboard.md`, статус 123 —
  `DEVELOPMENT_DONE`, "ручная проверка на устройстве не выполнена").
  126 добавляет изменения поверх непроверенной базы — риск, что баги
  123 и 126 будет сложно различить при первой проверке на устройстве.
- **`ArmbandView.vue` ограничен группой пользователя** — при "Freie
  Meldung" (CHECKIN, без фильтра по группе) сценарий "бейдж не найден →
  привязать" может привести на экран, где нужного ребёнка нет в списке
  (он не из группы сканирующего). Это существующее ограничение
  `/armband/:id`, не создаваемое и не устраняемое этим тикетом — но
  126 делает этот путь заметно более используемым (раньше до этого
  экрана нужно было дойти через QR-ссылку или прямой URL, теперь — одна
  кнопка при сканировании). Если на практике это окажется частой
  проблемой — отдельный тикет на доработку `ArmbandView.vue`
  (например, показывать детей всех групп с явным указанием группы).
- **Перенос `DailyCheckInModal` из `App.vue` в `MainView.vue`** —
  модалка перестаёт быть смонтированной глобально (во всех роутах) и
  монтируется только пока активен `/main`. Проверено грепом, что
  единственная точка её открытия — удаляемая кнопка в `App.vue`, других
  скрытых зависимостей не найдено — риск низкий, но стоит перепроверить
  при код-ревью, что ничего не полагалось на постоянное монтирование.
- **`onBindRequested` — новая опциональная точка входа в `Scanner.vue`,
  которую HeadcountView сознательно не использует** — решение
  зафиксировано в этом плане (различие в поведении `not-found` между
  полноэкранными режимами и Kopfzählung теперь намеренное, а не
  забытое), но об этом стоит явно упомянуть в
  `IMPLEMENTATION_REPORT.md`, чтобы будущий ревьюер не посчитал это
  недосмотром.
- **Единый ключ `localStorage` для настроек сканера** — миграция
  старого `scanner_preferred_camera_id` при первом чтении должна быть
  проверена на устройстве, где камера уже была выбрана до этого тикета
  (иначе пользователь молча вернётся к автоматическому режиму).
