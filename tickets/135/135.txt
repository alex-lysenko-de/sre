# Тикет 135: Экран Checkpoint — Lazy (реальный)

Часть фазы реализации Checkpoint — см. `tickets/131/MIGRATION_PLAN.md`.
Единственный полностью новый тип экрана (Bus/Group имеют прямых
предшественников в `AdminBusView.vue`/`ChildrenView.vue`, Lazy — нет) —
поэтому выделен отдельным тикетом, а не объединён с 134 (List+Bus+Group).

## Цель

Перенести `CheckpointLazyPrototypeView.vue` на реальные данные:
постепенная фиксация присутствия в течение дня — кто отметился, кто ещё
нет, время последней отметки, явный Finish без авто-завершения.

## Что прочитать перед началом

- `src/views/CheckpointLazyPrototypeView.vue` — эталонная раскладка.
- `src/composables/useLazyCheckpointProgress.js` (тикет 133) —
  `fetchLazyCheckpointProgress(checkpointId)`, реальный источник данных.
- `tickets/130/130.txt`, раздел «Ленивая перекличка (Lazy Roll Call)» —
  назначение: с часу до двух каждый ребёнок обязан отметиться (на базе
  или у ближайшего Betreuer); нет обязательного авто-завершения.
- `tickets/130/decision.md`, пп. 1-6 — авто-завершение Lazy при старте
  следующей Bus/Group-переклички (`130.txt:240`) отменено симметричной
  моделью: ни один тип не завершается автоматически.
- **Критерий готовности Lazy к Finish — решено, не открытый вопрос.**
  Простой список «ещё не отметились», без блокировки Finish и без
  временных порогов — то есть поведение `checkpointHasOpenIssues` (ветка
  LAZY, `notYet.length > 0` как предупреждение, не запрет) уже в моке —
  финальное решение, реализовать как есть, не искать другой критерий.

## Затрагиваемые части проекта

`src/views/`, `src/router/index.js` (маршрут Lazy-экрана, вместе с
маршрутами тикета 134 в общем namespace `/admin/checkpoints/...`).

## Файлы/подсистемы, которые будут изменены

- Новый файл `src/views/CheckpointLazyView.vue`.

## Что должно быть реализовано

1. Три списка/счётчика: «отметились» (с `checkedInBy`/временем), «ещё
   нет», «время последней отметки» — сгруппированные по группе
   (реалистичный масштаб ~150 детей, плоский список не навигируем — тот
   же вывод, что уже сделан в `useLazyCheckpointProgressMock.js`,
   комментарий Раунда 1 UX-фидбека).
2. Явный Finish (`useCheckpoints.finishCheckpoint`) — единственный способ
   закрыть Lazy-точку, с предупреждением при `notYet.length > 0`, без
   какого-либо автоматического завершения при старте другой точки.
3. Reopen/Remove — тот же паттерн, что у Bus/Group (тикет 134).
4. Обновление по Realtime, без «Aktualisieren».
5. Ссылки на карточки детей через `ChildLink` (тикет 133).

## Что не входит

- Изменение `ScannerCheckinView.vue`/«Freie Meldung» — не входит.
- Механизм авто-завершения Lazy — сознательно не реализуется.

## Результат выполнения тикета

- `CheckpointLazyView.vue` работает на реальных данных, доступен прямым
  переходом по маршруту.
- `npm run build` проходит без ошибок.
- Ручная проверка на устройстве: авто-создание Lazy-точки по первому
  CHECKIN-пакету, постепенное появление отметившихся детей в реальном
  времени, явный Finish с предупреждением.

## Зависимости

Требует 133. Независим от 134, 136. Блокирует 137.
