# Техническое задание

## Наименование

**Prompt Constructor** — настольное приложение для интерактивной сборки промптов из шаблонов.

---

# Цель

Предоставить пользователю инструмент для быстрого формирования промптов из заранее подготовленных шаблонов без ручного копирования и удаления ненужных частей текста.

Программа должна позволять:

* хранить роли в отдельных текстовых файлах;
* выбирать необходимые части инструкции посредством чекбоксов;
* автоматически подставлять номер тикета;
* сохранять пользовательские настройки между запусками;
* получать готовый текст, пригодный для копирования и дальнейшего использования.

---

# Общая архитектура

* Язык: **Python 3**
* GUI: **Tkinter (ttk)**
* Кодировка шаблонов: **UTF-8**
* Конфигурация: **INI**
* Все шаблоны находятся в текущем каталоге приложения.

---

# Формат шаблона

Каждый файл `*.txt` представляет собой один шаблон (роль).

Каждый шаблон состоит из обычного Markdown-текста и специальных секций.

Пример:

```text
Ты работаешь системным аналитиком.

Твои обязанности:

[SECTION name=tickets default=1]
Проверить тикеты.

Создать новый тикет {{TICKET}} при необходимости.
[/SECTION]

[SECTION class=git default=1]
Проверить git log...
[/SECTION]
```

В итоговый промпт управляющие конструкции не попадают.

---

# Формат SECTION

Начало секции:

```text
[SECTION ...]
```

Конец секции:

```text
[/SECTION]
```

Закрывающий тег обязателен.

Поддерживается произвольная вложенность.

---

# Атрибуты SECTION

## name

Необязательный.

Используется исключительно для сохранения состояния секции.

Если отсутствует:

* состояние секции не сохраняется;
* после открытия используется значение `default`.

Уникальность:

```
Имя файла + name
```

---

## class

Необязательный.

Объединяет несколько секций в логическую группу.

Все секции одного класса имеют единое состояние.

Изменение одной автоматически изменяет все остальные секции этого класса.

Независимое изменение отдельных секций одного класса невозможно.

---

## default

Необязательный.

Определяет состояние после Reset.

Правило:

```
default отсутствует → включено

default=1 → включено

default=0 → выключено
```

Другие значения не используются.

---

# Поддерживаемые плейсхолдеры

На текущем этапе поддерживается только

```
{{TICKET}}
```

Поле ввода номера тикета одно для всего приложения.

При генерации значение заменяет все вхождения во всех шаблонах.

---

# Интерфейс

Окно разделено вертикально.

## Левая панель

Содержит:

* вкладки (Notebook)

Каждая вкладка соответствует одному TXT-файлу.

Внутри вкладки отображаются:

* дерево SECTION;
* чекбоксы;
* визуальная вложенность.

Также сверху располагаются:

* поле "Ticket";
* кнопка **Generate**;
* кнопка **Reset**.

---

## Правая панель

Редактируемое текстовое поле.

Содержит последний сгенерированный промпт.

Пользователь может редактировать текст вручную.

Ниже располагается кнопка

```
Copy
```

которая помещает весь текст в буфер обмена.

---

# Логика загрузки

При запуске:

1. Найти все `*.txt` в текущем каталоге.
2. Отсортировать по имени файла.
3. Для каждого файла создать вкладку.
4. Разобрать шаблон.
5. Построить дерево SECTION.
6. Загрузить INI.
7. Применить сохранённые состояния.
8. Если сохранённого значения нет — использовать `default`.

Если файлов нет:

открывается пустое приложение.

---

# Логика генерации

Кнопка **Generate** выполняет полную генерацию заново.

Алгоритм:

1. пройти шаблон;
2. определить состояние каждой SECTION;
3. удалить отключённые SECTION полностью;
4. удалить управляющие теги;
5. заменить

```
{{TICKET}}
```

на введённое значение;
6. показать результат справа.

---

# Поведение редактора результата

После генерации пользователь может изменять текст вручную.

Если редактор изменён пользователем и нажата Generate:

показывается предупреждение:

> Текст был изменён вручную. Перегенерация удалит изменения.
> Продолжить?

При подтверждении редактор полностью заменяется новым результатом.

---

# Логика Reset

Reset не использует INI.

Reset устанавливает состояние согласно атрибуту `default`.

После Reset пользователь может снова выполнить Generate.

---

# Работа классов

Если несколько SECTION имеют одинаковый

```
class
```

то они образуют связанную группу.

Изменение состояния любой секции этой группы автоматически меняет состояние всех остальных.

Все они всегда имеют одинаковое состояние.

---

# Сохранение настроек

Используется INI.

Сохраняются:

* номер тикета;
* состояние SECTION, имеющих `name`;
* последняя открытая вкладка.

Не сохраняются:

* состояние SECTION без `name`;
* содержимое редактора результата.

---

# Формат хранения состояния

Ключ секции:

```
<имя файла>.<name>
```

Например

```
analyst.txt.tickets=true
```

---

# Правила разбора

Допускаются оба варианта записи атрибутов:

```
[SECTION name=test]
```

и

```
[SECTION name="test"]
```

Оба считаются корректными.

Порядок атрибутов произвольный.

---

# Бизнес-правила

* Все шаблоны имеют UTF-8.
* Закрывающий тег обязателен.
* Управляющие теги никогда не попадают в итоговый текст.
* Markdown не изменяется.
* Вложенность поддерживается без ограничений.
* SECTION без `name` не участвуют в сохранении состояния.
* `default=0` означает "выключено после Reset".
* Отсутствие `default` означает "включено".
* Изменение одной SECTION класса изменяет весь класс.

---

# Исключения и пограничные случаи

## Нет TXT

Открывается пустое приложение.

---

## Некорректная структура

Ошибками считаются:

* отсутствующий `[/SECTION]`;
* пересекающиеся SECTION;
* некорректная вложенность.

В этом случае файл не должен использоваться для генерации. Пользователю следует показать понятное сообщение с указанием файла и места ошибки.

---

## Неизвестные атрибуты

Игнорируются.

---

## Повторяющийся name

Допустим только в разных файлах.

В пределах одного файла считается ошибкой.

---

## Повторяющийся class

Допускается.

---

## Пустая SECTION

Допускается.

---

## Пустой Ticket

Допускается.

В этом случае

```
{{TICKET}}
```

заменяется пустой строкой.

---

# Нефункциональные требования

* Поддержка Windows.
* Использование только стандартной библиотеки Python.
* Время открытия приложения — не более 1 секунды при наличии до 100 шаблонов среднего размера.
* Интерфейс должен корректно работать при масштабировании Windows (High DPI).
* Все операции выполняются локально, без сетевого взаимодействия.

---

# Acceptance Criteria

1. При запуске автоматически создаются вкладки по числу TXT-файлов.
2. Каждый шаблон корректно разбирается на SECTION.
3. Вложенность SECTION отображается в интерфейсе.
4. Изменение состояния чекбокса влияет на итоговую генерацию.
5. Изменение любого чекбокса класса автоматически изменяет все чекбоксы этого класса.
6. Generate полностью пересобирает промпт.
7. Управляющие теги отсутствуют в результате.
8. Все `{{TICKET}}` заменяются введённым значением.
9. Copy помещает весь результат в буфер обмена.
10. Reset восстанавливает состояния согласно `default`.
11. При повторном запуске восстанавливаются сохранённые состояния именованных SECTION.
12. При повторном запуске восстанавливается номер тикета.
13. При повторном запуске открывается последняя активная вкладка.
14. Ручное изменение результата вызывает предупреждение перед повторной генерацией.
15. SECTION без `name` никогда не сохраняются в INI.
16. Программа корректно работает с вложенными SECTION.
17. Некорректный шаблон не приводит к аварийному завершению приложения.
