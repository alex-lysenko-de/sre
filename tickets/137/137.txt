# Тикет 137: `CheckpointListView.vue` (реальный) + маршруты + кнопка в `MainView.vue`

Часть фазы реализации Checkpoint — см. `tickets/131/MIGRATION_PLAN.md`.
Первый реальный экран Checkpoint, точка входа. Работает **рядом** со
старыми `/admin-busses`/`/children` — они не удаляются в этом тикете
(Phase 2, тикет 143).

## Цель

Перенести `CheckpointListPrototypeView.vue` на реальные данные: список/
история контрольных точек за день, явное создание (тип-селектор),
переход в детальный экран по клику.

## Что прочитать перед началом

- `src/views/CheckpointListPrototypeView.vue` — эталонная раскладка и
  логика.
- `src/components/checkpoints-prototype/CheckpointCreateModal.vue`,
  `CheckpointStatusBadge.vue`, `CheckpointTypeBadge.vue`,
  `CheckpointOriginBadge.vue` — переиспользуемые компоненты (badge
  «Admin» vs «Auto (Betreuer X)» — обязателен, не может отсутствовать,
  `131.txt`, «Открытые вопросы»).
- `src/composables/useCheckpoints.js` (тикет 135, должен быть готов) —
  реальный источник данных вместо мока.
- `tickets/130/decision.md`, п. 3 — несколько одновременно открытых
  контрольных точек разных типов — нормальное состояние, список не
  должен подсвечивать это как ошибку/конфликт.
- `tickets/131/IMPLEMENTATION_PLAN.md`, раздел «UI изменения» — точные
  предлагаемые маршруты (`/admin/checkpoints`, `/admin/checkpoints/list`
  и т.д. — пример, не обязательное значение, финализировать по месту).
- `src/views/MainView.vue:74-121` — три текущие кнопки («Busse»,
  «Admin Übersicht», «Checkpoints (Prototyp)») — этот тикет добавляет
  **четвёртую**, реальную, не убирая остальные три (объединение меню —
  тикет 143).

## Затрагиваемые части проекта

`src/views/`, `src/router/index.js`, `src/views/MainView.vue`.

## Файлы/подсистемы, которые будут изменены

- Новый файл `src/views/CheckpointListView.vue` (копия
  `CheckpointListPrototypeView.vue` без суффикса `Prototype`, без
  `DebugTag`/`Page N`/`elN` — они были нужны только для UX-согласования
  130_2).
- `src/router/index.js` — новые маршруты (например
  `/admin/checkpoints`, `/admin/checkpoints/list`), без удаления
  `-prototype`-маршрутов (остаются до Phase 2/до подтверждения, что
  прототип больше не нужен для сравнения).
- `src/views/MainView.vue` — новая кнопка «Checkpoints», рядом с
  существующими тремя (`v-if="userStore.isAdmin"`, тот же паттерн).

## Что должно быть реализовано

1. Список/история контрольных точек текущего дня через
   `useCheckpoints.fetchCheckpointsForDay(day)` + Realtime-подписка
   (`subscribeToCheckpointsChanges`, тикет 135) — без кнопки
   «Aktualisieren».
2. Явное создание через `CheckpointCreateModal` → `useCheckpoints.
   createCheckpoint(type)`; обработка `{error: 'ALREADY_OPEN',
   existingId}` — сообщение и/или переход к существующей открытой точке.
3. Клик по строке → переход на детальный экран нужного типа (маршрут
   зависит от `checkpoint.type` — Bus/Group/Lazy, экраны из тикетов
   138–140).
4. Визуальное отличие точек, открытых одновременно разных типов —
   не как ошибка (см. `decision.md`, п. 3); визуальное выделение
   аварийного состояния «две открытые одного типа» — как аномалии, если
   оно всё же встретилось (`decision.md`, п. 6) — по образцу прототипа.
5. Бейдж «создана автоматически (Betreuer X)» / «создана
   администратором» — обязателен на каждой строке.

## Что не входит

- Удаление/замена `/admin-busses`/`/children` — Phase 2, тикет 143.
- Детальные экраны Bus/Group/Lazy — тикеты 138–140 (этот тикет может
  временно вести на заглушку/старый прототип-маршрут до их готовности,
  если тикеты выполняются не строго последовательно).

## Результат выполнения тикета

- `CheckpointListView.vue` работает на реальных данных, доступен по
  новому маршруту, кнопка в `MainView.vue` на месте.
- `npm run build` проходит без ошибок.
- Ручная проверка на устройстве: создание/просмотр списка на реальной
  БД (после 132–135).

## Зависимости

Требует 135 (composable-слой), 136 (entity-компоненты, если список
показывает ссылки на Betreuer-создателя точки). Не блокирует 138–140
напрямую (они не зависят друг от друга), но логически идёт первым, так
как это точка входа/навигации к ним.
