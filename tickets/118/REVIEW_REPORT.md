# Critical

1. **Необъяснённое удаление ссылки из `vault/00-Индекс/MOC.md`, выходящее за
   рамки заявленного скоупа тикета.**
   Диф коммита `c332569`:
   ```diff
    ## 04 — Пользователи и аутентификация

    - [[Модель-аутентификации]]
   -- [[Инвайты-сессии-WebAuthn]] — invites/sessions/WebAuthn, что из этого реально используется
    - [[useUser]]
   ```
   Файл `vault/04-Пользователи-и-аутентификация/Инвайты-сессии-WebAuthn.md`
   при этом **не удалён и не изменён** — он просто выпал из индекса и стал
   недостижим через `MOC.md`, единственную заявленную "точку входа" (см.
   сам `CLAUDE.md`, создаваемый этим же тикетом: "Точка входа в полную базу
   знаний — `vault/00-Индекс/MOC.md`").
   - `IMPLEMENTATION_PLAN.md` прямо ограничивает изменения `vault/` одним
     точечным риском (атрибуция в `Кэширование-LocalForage.md`): "vault/ —
     эталон для сравнения, **не изменяется** в рамках этого тикета (кроме
     одного точечного риска, см. раздел «Риски»)". Второе изменение `vault/`
     не согласовано и не упомянуто нигде.
   - `IMPLEMENTATION_REPORT.md` в разделе "Измененные файлы" перечисляет
     только один изменённый файл `vault/` (`Кэширование-LocalForage.md`).
     Изменение `MOC.md` не задокументировано вообще — то есть отчёт
     разработчика фактически неполон/неточен относительно реального диффа.
   - Сама заметка `Инвайты-сессии-WebAuthn.md` описывает потенциально
     небезопасный, не подключённый к фронтенду слой аутентификации
     (WebAuthn/passkey + кастомный JWT с fallback-секретом
     `'your-secret-key'` в коде) — это заметка не проходная, а
     содержательно значимая находка предыдущего ревью (тикет 108, Critical
     2). Молчаливое исключение её из навигационного индекса — это
     фактический откат части исправления из тикета 108 без объяснения,
     и именно тот тип "потери знаний из-за неаккуратной уборки", от
     которого должен защищать сам тикет 118.
   - **Требуется:** либо вернуть строку в `MOC.md` (если удаление
     случайное), либо явно задокументировать в `IMPLEMENTATION_REPORT.md`
     причину, по которой заметка исключается из индекса, и получить
     согласование, поскольку это выходит за рамки DoD тикета 118.

# Major

1. **Массовые "мёртвые" атрибуции `Источник: doc/....md` в `vault/`,
   указывающие на файлы, которые тикет только что удалил.**
   Помимо единственного точечного риска, явно разобранного в плане
   (`doc/migration_guide.md` → `Кэширование-LocalForage.md`), в `vault/`
   остаётся минимум 14 заметок, дословно указывающих один из 9 удалённых
   файлов `doc/` как "Источник" (проверено `grep` по `vault/` после
   коммита), например:
   - `vault/02-Предметная-область/Идентификация-ребёнка.md:3` —
     `> Источник: doc/info.md, doc/QR-codes.md, doc/ArmbandTask.md.`
   - `vault/01-Архитектура/Целевая-архитектура.md:3` —
     `> Источник: doc/info.md, раздел «Архитектурные принципы».`
   - `vault/04-Пользователи-и-аутентификация/Модель-аутентификации.md:3,16,46`
     — три ссылки на `doc/useUser.md` / `doc/selectGroupAndBus.md`.
   - `vault/03-База-данных/Обзор-схемы-БД.md`, `groups_today.md`,
     `scans.md`, `users.md`, `children.md`, `config.md`, `days.md`,
     `user_group_day.md`, `reset_events.md` — все ссылаются на
     `doc/table_structure.md` (и/или `doc/db_triggers.sql`, который остаётся
     на месте — там проблемы нет).
   - `vault/02-Предметная-область/Группы-и-рабочий-день.md:42,47` —
     ссылки на `doc/selectGroupAndBus.md`.
   - `vault/02-Предметная-область/Учёт-автобусов.md:3` — на `doc/info.md`,
     `doc/AdminBusView_TechTask.md`, `doc/db/adminBusView.md`.
   - `vault/05-API-Composables/useArmband.md:3`, `useBusData.md:4` —
     на `doc/ArmbandTask.md` / `doc/AdminBusView_TechTask.md`.
   - `vault/06-Маршруты-и-URL/QR-код-URL.md:3,27` — на `doc/QR-codes.md`.
   - `vault/00-Индекс/_Конвенции.md:14` — на `doc/info.md`.

   Это в точности тот класс риска, который план явно выделил и разрешил для
   одного файла ("После удаления `doc/migration_guide.md` эту цитату в
   `vault/` будет невозможно перепроверить по первоисточнику"), но не
   распространил на остальные 13+ мест с идентичной структурой проблемы.
   Разработчик, судя по всему, тоже не заметил обобщённость проблемы —
   в отчёте зафиксирована сверка только по одному файлу-атрибуции.
   Содержательно данные не потеряны (перенесены в `vault/` корректно, это
   подтверждено выборочной проверкой), но сам механизм "проверяемости по
   первоисточнику", на котором стоит методология аудита `vault/` (см. те же
   формулировки "Источник:"), теперь для 9 файлов сломан навсегда — цитаты
   ссылаются в никуда. Это системный технический долг, а не изолированный
   баг, и его стоит закрыть либо здесь, либо явным follow-up-тикетом
   (заменить дословные пути `doc/X.md` на пометку вида "исходный файл
   удалён в тикете 118, содержание перенесено сюда").

2. **Backlog-заметка похоронена внутри закрытого тикета, без единой ссылки
   извне.**
   `tickets/118/AdminBusView_Backlog.md` (7 нереализованных идей,
   единственная цель существования файла — не потерять их) не
   ссылается и на неё не ссылается ничто, кроме самого
   `IMPLEMENTATION_REPORT.md` (проверено `grep` по всему репозиторию).
   Ни `CLAUDE.md`, ни `tickets/dashboard.md`, ни `vault/` не содержат
   указателя на этот файл. Через несколько тикетов эта заметка станет
   так же трудно обнаружимой, как исходный `AdminBusView_TechTask.md`
   до этого тикета — то есть цель "не потерять backlog" достигнута лишь
   формально (файл физически существует), а не по существу
   (обнаружимость). План этого явно не требовал ("backlog-заметка или
   прямая запись в тикет" — буква плана соблюдена), но стоит либо
   добавить ссылку из `tickets/dashboard.md`, либо перенести в
   `vault/` как заметку о нереализованных фичах.

2. `tickets/dashboard.md` фиксирует статус тикета 118 как
   `DEVELOPMENT_DONE` — сам файл не под ревью в этом тикете, но раз DoD
   требует "обновить `tickets/dashboard.md`", финальный проход после этого
   ревью должен также синхронизировать статус (`DONE`/`CHANGES_REQUIRED`)
   после того как замечания будут закрыты.

# Архитектурные замечания

- Соглашение "заметка `vault/` = самостоятельный источник правды, ссылки на
  `doc/` — не более чем 'откуда это изначально пришло'" в целом выдержано
  корректно — там, где `vault/`-заметка явно указывает, что первичный
  источник теперь код (`src/...`), а не `doc/`-файл (`useArmband.md`,
  `useUser.md`, `stores-user.md`), это сделано аккуратно и в духе тикета
  108. Проблема из Major №1 — именно в оставшихся местах, где `doc/X.md`
  всё ещё указан как "Источник" без такой переадресации.
- Решение зафиксировать факт о `group_id`/`bus_id` ("поля на сегодня", не
  персистентные атрибуты) прямо в `CLAUDE.md` — хороший пример именно того
  нетривиального факта, который тикет и должен был вынести на поверхность
  (не выводится тривиально чтением схемы, легко перепутать).
- Пункт про коллизию номеров тикетов (`17e206d "111: ..."`) полезен и
  корректно задокументирован и в `CLAUDE.md`, и косвенно подтверждён
  историей — сам тикет 118 действительно фигурирует в `118.txt`/каталоге,
  а не под номером 111, что соответствует описанному процессу.
