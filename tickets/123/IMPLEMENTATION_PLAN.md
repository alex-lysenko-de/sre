# Цель

Переработать интерфейс Kopfzählung (`HeadcountView.vue`) из карточно-списочной
раскладки в плотную табличную, по образцу бумажного списка присутствия:
весь список группы на одном экране, стабильный порядковый номер, два
столбца-индикатора присутствия (Morning/Current), ручная отметка кликом по
чекбоксу — без изменения существующей серверной модели данных.

Дополнительно (п. 7-8 тикета, не вариативная часть) — встроить в этот же
экран кнопку «Scan», открывающую выезжающую сверху панель со сканером
(тот же сканер и та же бизнес-логика обработки результата, что в режиме
Gruppen-Appell тикета 120), с автозакрытием панели через 5 секунд простоя
после последнего успешного скана.

Задача архитектурная: спроектировать решение и подготовить варианты
табличной раскладки для выбора, не реализуя и не меняя код.

# Анализ текущей архитектуры

## Текущий `HeadcountView.vue`

Карточка (`.card`) со списком `<li>` (list-group), каждая строка — имя,
возраст, бейдж "Morgens" (только чтение), переключатель "Jetzt anwesend".
Список не пронумерован, порядок — по имени ребёнка (см. ниже). Экран
занимает много места на декоративные отступы/карточку — ровно то, что п.1
требования просит сократить.

Загрузка данных — `Promise.all(fetchChildrenByGroup(groupId), getTodayGroupPresence(groupId))`
при `created()`; ручная отметка — `onTogglePresentNow()` →
`useChildPresence.setPresentNow()`.

## `useChildPresence.js` — путь ручной отметки (не меняется)

- `getTodayGroupPresence(groupId)` — читает `children_today` по `group_id`
  (`presence_morning`, `presence_now`).
- `setPresentNow(childId, groupId, isPresent, currentUserId)` — прямой
  upsert `children_today.presence_now`, **никогда не пишет
  `presence_morning`** (явный комментарий в коде) и не создаёт запись в
  `scans`. Это один из двух путей записи, которые тикет 122 явно защитил
  регрессионной проверкой при переработке триггеров под пакетную модель —
  переиспользуется этим тикетом as-is, без изменений сигнатуры/поведения.

## `useChildren.fetchChildrenByGroup(groupId)` — источник списка детей

Возвращает `id, name, age, band_id`, отсортированные `.order('name')`.
Проверено (`grep`): единственный потребитель во всём проекте —
`HeadcountView.vue`. Значит сортировку можно изменить без риска
побочных эффектов в других экранах.

## Инвариант `presence_morning` (write-once)

`children_today.presence_morning` устанавливается ровно один раз — в
INSERT-ветке `ON CONFLICT` триггера `on_scan_insert` (в перспективе —
его пакетной версии из тикета 122), то есть **только при первой записи
в `scans`** для ребёнка в этот день. Путь ручной отметки Kopfzählung его
никогда не трогает (см. выше). Это существующий, задокументированный
(`vault/03-База-данных/children_today.md`, тикеты 106/122) инвариант —
123 не имеет права его нарушать.

## Подсистема сканера (116/120) — переиспользуемый строительный блок

- `Scanner.vue` — камера/декод/базовый фидбек (звук, вибрация, экран
  подтверждения). Не знает о режимах (Bus/Gruppe/Checkin). Контракт —
  обязательный проп `onChildResolved(result) → {title, subtitle,
  variant?, repeat?} | undefined`, плюс `defineExpose({ stop,
  showMessage })`. Сегодня всегда монтируется как содержимое целого
  экрана одного из маршрутов `/scanner/bus|group|checkin` — **прецедента
  встраивания `Scanner.vue` как временной сворачиваемой панели внутри
  другого экрана в проекте ещё нет**, п. 7-8 этого тикета вводят такой
  прецедент впервые.
- `ScannerGroupView.vue` (режим Gruppen-Appell, тикет 120) — ближайший
  функциональный аналог того, что требует п. 7: создаёт пакет
  `useScanPacket.createPacket('GROUP', {group_id})`, на каждый
  `result.status === 'found'` проверяет `child.group_id !== groupId`
  (иначе — бизнес-ошибка «Kind gehört nicht zu dieser Gruppe», ребёнок
  не попадает в пакет), проверяет `isDuplicate()`, вызывает
  `addScanned()`/`addManual()`, по кнопке — `submitPacket()` в Edge
  Function `submit-scan-packet` (тикет 122). Формулировка п. 7 тикета
  123 («processed exactly as defined for Gruppen-Scan») требует
  переиспользовать именно эту модель обработки, а не прежний
  прямой `INSERT` в `scans`/`setPresentNow()`.
- `useScanPacket.js` — универсальный composable пакета (BUS/GROUP/
  CHECKIN); `submitPacket()` идемпотентен относительно повторного вызова
  при ошибке (тот же `client_packet_id`/`finished_at` сохраняется).

## Риск окружения (внешний по отношению к 123, но блокирующий его проверку)

Согласно `tickets/dashboard.md` (строка 122) и
`tickets/122/IMPLEMENTATION_REPORT.md`, применение SQL-схемы
`scan_packets` к боевой БД, деплой Edge Function `submit-scan-packet` и
сквозная проверка с тикетом 120 на реальном устройстве всё ещё
выполняются вручную и, по последним данным, не подтверждены как
выполненные в целевом окружении. Без этого сканирующая часть 123 не
может быть проверена end-to-end (см. «Риски»).

# Изменения существующих компонентов

## `useChildren.js` — `fetchChildrenByGroup(groupId)`

`.order('name', { ascending: true })` → `.order('id', { ascending: true })`.

Обоснование: п. 3 требования — стабильный, не зависящий от возможного
переименования ребёнка порядок, с отображаемым порядковым номером.
Единственный потребитель функции — `HeadcountView.vue` (подтверждено
поиском по проекту), изменение сортировки не затрагивает никакой другой
экран. Сортировка по `id` уже является существующим прецедентом для
ростера в похожем сценарии (`useArmband.getChildrenByGroupOrderedById()`,
используется в `ScannerGroupView.vue`) — решение согласовано с уже
принятым в проекте подходом, а не вводит новый.

## `HeadcountView.vue`

- Загрузка данных (`Promise.all(fetchChildrenByGroup, getTodayGroupPresence)`)
  сохраняется без изменений в бизнес-логике; меняется только раскладка
  вывода и обработка результата сканирования.
- Ручная отметка (`onTogglePresentNow()` → `setPresentNow()`) переносится
  без изменений сигнатуры и семантики.
- Добавляются: порядковый номер строки, кнопка «Scan» над таблицей,
  выезжающая панель со встроенным `Scanner.vue`, условное скрытие
  столбца Morning (см. «UI изменения» и «Риски»).

# Новые компоненты

## `src/composables/useGroupScanSession.js`

Инкапсулирует состояние встроенной сессии сканирования Kopfzählung:

- Обёртка над `useScanPacket`: `createPacket('GROUP', { group_id })` при
  открытии панели.
- Бизнес-правило «чужая группа» — то же условие и то же сообщение, что в
  `ScannerGroupView.handleResolved()` (`child.group_id !== groupId`).
- Проверка дубликата — `scanPacket.isDuplicate()`.
- Таймер бездействия (5 секунд от последнего **успешного** скана,
  сбрасываемый каждым новым успешным сканом) — по истечении инициирует
  закрытие панели и фоновую `submitPacket()`.
- Отражение результата сразу в переданный по ссылке список детей экрана
  (`presentNow = true`) — для немедленного обновления таблицы независимо
  от завершения сетевого запроса (тот же паттерн, что
  `ScannerGroupView.markRosterFound()`, но пишет в общий список
  Kopfzählung, а не в отдельный ростер).
- Состояние ошибки отправки и функция повторной отправки (переиспользует
  идемпотентность `submitPacket()` — тот же `client_packet_id`).

Почему отдельный composable, а не логика прямо в `HeadcountView.vue`:
экран и так получает существенно более сложный template (таблица +
панель сканера); вынесение бизнес-правил сессии сканирования в отдельный
модуль позволяет не разрастить `HeadcountView.vue` до трудноподдерживаемого
размера и оставляет возможность (вне рамок этого тикета) в будущем свести
дублирующуюся с `ScannerGroupView.vue` бизнес-логику к одному источнику.

Рефакторинг `ScannerGroupView.vue` под этот новый composable **не
входит** в 123 (вне заявленной области задачи, п. «Ограничения»
общей инструкции — «не добавлять функциональность вне требований»);
временное дублирование правила «чужая группа»/«дубликат» между двумя
местами зафиксировано в разделе «Риски».

# UI изменения

## Панель сканера (единая архитектура, не вариативная часть)

- Кнопка «Scan» — над таблицей, полноширинная, в её обычном месте в
  потоке документа.
- По нажатию — выезжающая сверху панель (slide-down), занимающая
  примерно верхнюю четверть-половину экрана; внутри — `Scanner.vue` без
  изменений его собственного контракта. Таблица остаётся видимой ниже
  панели (не перекрывается модальным затемнением).
- `onChildResolved` панели подключён к `useGroupScanSession` — успешный
  скан «своего» ребёнка сразу переключает соответствующую строку таблицы
  в состояние «Current = присутствует» и сбрасывает 5-секундный таймер
  бездействия.
- По истечении 5 секунд без нового успешного скана — панель уезжает
  обратно вверх (`Scanner.vue` размонтируется, останавливая камеру),
  кнопка «Scan» возвращается на своё место, накопленный пакет
  отправляется в фоне через `submitPacket()`.
- Ошибка фоновой отправки — компактное сообщение рядом с кнопкой «Scan»
  с действием «Повторить» (переиспользует идемпотентность `submitPacket()`,
  без отдельного экрана и без отката уже выставленных в таблице отметок —
  тот же принятый риск, что и в `ScannerGroupView.vue`).

## Табличная раскладка — два альтернативных концепта (на выбор)

Согласно собственному разделу тикета «Deliverable», этот пункт — не
окончательный дизайн, а материал для сравнения перед выбором одного
варианта для реализации. Оба концепта используют одну и ту же архитектуру
данных и панели сканера выше — различаются только представлением строки
таблицы.

**Концепт A — «классическая таблица» (буквально по примеру из 123.txt)**

```
 №  Kind              Morgens   Jetzt
 1  Ivanov               ☑        ☑
 2  Petrov               ☑        ☐   ← красноватый фон строки
 3  Sidorov              ☐        ☑
```

- `table table-sm`, без карточки-обёртки, без внешних отступов —
  таблица растягивается на всю ширину экрана.
- Столбец Morgens — нативный `<input type="checkbox" disabled>` (только
  чтение); столбец Jetzt — нативный чекбокс, `@change` вызывает тот же
  `setPresentNow()`, что и сегодня.
- Строки с `Jetzt = false` — подсвечены (перенос текущего
  `bg-danger-subtle`) для мгновенного визуального выявления отсутствующих
  (п. «Expected Result», «immediately identify missing children»).
- Столбец Morgens целиком скрывается, если ни у одного ребёнка группы
  ещё нет `presence_morning = 1` за сегодня (см. «Риски» —
  приближённое, не точное решение п. 5 требования).

**Концепт B — «таблица с тап-плашкой присутствия»**

```
 №  Kind              Morgens   Jetzt
 1  Ivanov                ✓    [ANWESEND]
 2  Petrov                ✓    [ FEHLT  ]  ← вся плашка красная
 3  Sidorov                –   [ANWESEND]
```

- Morgens — не чекбокс (он и так недоступен для ввода), а маленькая
  текстовая/иконочная отметка (✓/–), чтобы не создавать ложное
  впечатление интерактивности.
- Jetzt — полноширинная (в пределах ячейки) плашка-кнопка с текстом
  состояния, а не мелкий нативный чекбокс — увеличенная область
  касания для использования на телефоне во время переклички; формально
  остаётся «эквивалентной отметкой» в терминах п. 4 требования
  («checkboxes (or equivalent check marks)»).
- Та же логика скрытия столбца Morgens, что в концепте A.
- Компромисс: выше визуальная плотность на строку (шире Jetzt-ячейка),
  чем в концепте A, но лучше эргономика попадания пальцем.

Оба концепта совместимы без изменений с архитектурой панели сканера,
`useGroupScanSession.js` и изменением сортировки в `useChildren.js` —
выбор между ними не влияет ни на один другой раздел этого плана.

# План реализации

1. Ревью и выбор одного из двух табличных концептов (или согласованная
   комбинация их элементов) — контрольная точка с заказчиком, как явно
   указано в разделе «Deliverable» тикета 123.txt, до начала кода.
2. Подтвердить, что серверная инфраструктура тикетов 120/122
   (`scan_packets`, `submit-scan-packet`) реально развёрнута и достижима
   в целевом окружении — блокирующая зависимость для проверки
   сканирующей части (см. «Риски»); если не развёрнута — синхронизация с
   владельцами 120/122 до перехода к шагам 5-7.
3. Сменить сортировку в `useChildren.fetchChildrenByGroup()` на `id`.
4. Реализовать выбранную табличную раскладку `HeadcountView.vue` с уже
   существующими данными (без встраивания сканера) — проверить п. 1-6
   требования изолированно от сканера.
5. Реализовать `useGroupScanSession.js`.
6. Встроить кнопку «Scan» и выезжающую панель `Scanner.vue` в
   `HeadcountView.vue`, подключить к `useGroupScanSession.js`.
7. Ручная регрессионная проверка на устройстве: путь ручной отметки
   (чекбокс/плашка → `setPresentNow()`) не сломан; путь скана обновляет
   таблицу немедленно и реально сохраняется на сервере через
   `submit-scan-packet`; автозакрытие через 5с простоя; повторное
   открытие панели начинает новую сессию; повтор отправки после сбоя не
   создаёт дублей.
8. Проверка условного скрытия столбца Morgens в двух сценариях: (а) уже
   есть автобусные сканы за сегодня у части группы, (б) вся группа ещё
   не имеет ни одного скана за сегодня (см. «Риски»).

# Риски

- **Незавершённое серверное окружение 120/122.** Сканирующая часть 123
  не может быть проверена end-to-end, пока `scan_packets`/
  `submit-scan-packet` не развёрнуты и не подтверждены совместным
  тестом 120+122 (см. «Анализ текущей архитектуры»). Табличная часть
  (п. 1-6) от этой зависимости не страдает и может разрабатываться и
  проверяться независимо.
- **Дублирование бизнес-правила между `ScannerGroupView.vue` и
  `useGroupScanSession.js`.** Осознанно принято (см. «Новые компоненты»)
  вместо рефакторинга вне области задачи; при будущем изменении правила
  «чужая группа»/«дубликат» нужно будет менять оба места.
- **Оптимистичное обновление таблицы до подтверждения сервера.** Строка
  переключается в «присутствует» сразу по успешному скану, до
  завершения фоновой `submitPacket()`; при неоднократном сбое отправки
  таблица может визуально показывать присутствие, ещё не сохранённое на
  сервере — тот же принятый в 120 риск (`ScannerGroupView.vue`),
  переносится без изменений, смягчается только видимым «Повторить», не
  откатом отметки.
- **Неполное покрытие п. 5 требования (первая перекличка дня = утренняя).**
  Автоматически это выполняется только когда первое сегодняшнее действие
  по ребёнку — скан (пишет в `scans`, взводит `presence_morning` через
  существующий триггер). Если первая перекличка дня для ребёнка проходит
  целиком вручную (чекбокс/плашка, путь `setPresentNow()`, никогда не
  пишущий `presence_morning`), эвристика «скрывать столбец Morgens, пока
  ни у кого в группе нет `presence_morning=1`» не отличает «утро ещё не
  было» от «утро было, но исключительно вручную» — приближённое, а не
  точное решение, как и допускает формулировка требования («handle this
  case automatically... hiding the column»).
- **Новый паттерн использования `Scanner.vue`.** Ранее компонент
  монтировался один раз на весь визит на выделенный маршрут; здесь он
  многократно монтируется/размонтируется в рамках одного визита экрана
  (открытие → автозакрытие → повторное открытие). Поведение инициализации/
  остановки камеры при быстром повторном открытии требует проверки на
  реальном устройстве, не только в браузере на десктопе (тот же класс
  риска, что уже фиксировался при работе над 116/120).

# Definition of Done

- Таблица показывает всю группу на одном экране без прокрутки по
  отдельным карточкам, с порядковым номером, стабильным между
  перезагрузками (сортировка по `id`).
- Ручная отметка присутствия работает кликом по чекбоксу/плашке в
  таблице без сканера, путь `setPresentNow()` не изменён и
  регрессионно проверен.
- Кнопка «Scan» открывает выезжающую сверху панель (~1/4–1/2 экрана),
  таблица остаётся видимой под ней.
- Успешный скан ребёнка своей группы немедленно отражается отметкой
  «присутствует» в соответствующей строке таблицы.
- Отсканированные данные реально долетают до сервера тем же путём
  (`submit-scan-packet`, тип `GROUP`), что и режим Gruppen-Appell
  тикета 120 — подтверждено после развёртывания серверной части 122.
- После 5 секунд без нового успешного скана панель автоматически
  закрывается, кнопка «Scan» возвращается на место; повторное открытие
  начинает новую сессию сканирования.
- Столбец Morgens корректно скрывается/появляется согласно эвристике
  раздела «UI изменения» в обоих сценариях шага 8 плана реализации.
- Проверено на реальном устройстве (не только в браузере на десктопе).
