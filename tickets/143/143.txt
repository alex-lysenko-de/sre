# Тикет 143: Удаление устаревшего кода + объединение меню администратора

Часть фазы реализации Checkpoint — см. `tickets/131/MIGRATION_PLAN.md`.
Финальный функциональный тикет Phase 2: Checkpoint-функциональность
(Phase 1 + Phase 2 БД) уже подтверждена (тикеты 141, 142) — теперь старый
механизм безопасно удаляется, а не просто перестаёт вызываться.

## Цель

Удалить мёртвый/замещённый код (`AdminBusView.vue`, `ChildrenView.vue`,
`ResetHistoryPanel.vue`, неиспользуемые функции `useDays.js`, триггер
`on_reset_event_insert`), объединить пункты меню администратора в
`MainView.vue`, обновить `router/index.js` (Checkpoints заменяет
`/admin-busses`/`/children`, `-prototype`-маршруты удаляются).

  администратора» — что должно произойти с Hard Reset/Soft Reset/

- `tickets/130/IMPLEMENTATION_PLAN.md`, раздел «План реализации», п. 9 —

- `tickets/131/MIGRATION_PLAN.md`, §1.3, п.1 и п.6 — подтверждённые
  расхождения (авто-завершение Lazy отменено; `closeDay`/`isDayClosed`

- `src/composables/useDays.js` целиком — какие функции остаются

  `isDayStarted`, `isDayClosed`), какие используются в другом месте
  (сверить грепом перед удалением каждой — не полагаться только на этот

## Файлы/подсистемы, которые будут изменены

- **Удаляются**: `src/views/AdminBusView.vue`, `src/views/ChildrenView.vue`,
  `src/components/ResetHistoryPanel.vue`, все `*PrototypeView.vue`/
  `*Mock.js`/`src/components/checkpoints-prototype/*` (заменены реальными
  эквивалентами в тикетах 136–140 — удалять только после подтверждения,
  что ни один маршрут/импорт на них больше не ссылается).
- `src/composables/useDays.js` — удаление `startNewDay`/`softReset`/
  `closeDay`/`isDayStarted`/`isDayClosed`; `fetchDaysList`/`saveDay`/
  `deleteDay` (управление `days`-справочником) остаются — они не связаны
  с Reset-механизмом.
- `src/composables/useBusData.js` — удаление `getResetHistory()`.
- `src/router/index.js` — удаление маршрутов `/admin-busses`, `/children`,
  всех `*-prototype`-маршрутов; финальные пути Checkpoint (уже введённые
  в 137–140) становятся единственными.
- `src/views/MainView.vue` — кнопки «Busse» (:74-88), «Admin Übersicht»
  (:91-105), «Checkpoints (Prototyp)» (:107-121) заменяются одной кнопкой
  «Checkpoints», ведущей на реальный `CheckpointListView.vue` (тикет 137).
- `doc/db_triggers.sql`/БД — удаление триггера `trg_on_reset_event_insert`
  и функции `on_reset_event_insert()` (новый файл-миграция
  `doc/db/remove_reset_events_trigger.sql`, `DROP TRIGGER`/`DROP
  FUNCTION`, не редактирование `doc/db_triggers.sql` задним числом —
  проект хранит миграции как последовательность файлов, не единый
  редактируемый файл, см. конвенцию `doc/db/scan_packets.sql`).

## Что должно быть реализовано

1. Грепом подтвердить отсутствие оставшихся потребителей для каждого
   удаляемого файла/функции перед удалением (не удалять «по списку из
   документа» вслепую — список составлен на момент написания 130/131,
   могло измениться).
2. Удаление файлов/функций из списка выше.
3. `MainView.vue` — одна кнопка «Checkpoints» вместо трёх, тот же паттерн
   (`v-if="userStore.isAdmin"`).
4. `router/index.js` — актуальный набор маршрутов без старых/прототипных
   путей.
5. **Не удаляется** в этом тикете: `reset_events` как таблица (данные —
   история, не мешают; удаление таблицы — не требуется ни одним
   документом, только связанный триггер и клиентские вызовы).
6. `BusDetailModal.vue`/`GroupDetailModal.vue` — удаляются только если
   полностью замещены (не переиспользованы как основа новых экранов в
   138/139, где они использовались как «источник вёрстки», не как
   компонент-зависимость) — проверить импорты перед удалением.

## Что не входит

- Удаление таблиц `reset_events`/`children`/`users`/схемы — не входит.
- Любые новые функциональные изменения — только удаление/объединение.

## Результат выполнения тикета

- Единственная точка входа администратора — «Checkpoints».
- `npm run build` проходит без ошибок, нет мёртвых импортов.
- Ручная проверка на устройстве: старые маршруты (`/admin-busses` и
  т.д.) больше не существуют (редирект/404 по политике приложения),
  новый флоу полностью покрывает прежнюю функциональность.
