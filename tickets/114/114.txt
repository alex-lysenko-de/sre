# Bug fix: редирект на /info после логина/регистрации вместо home page

## Проблема

Когда пользователь входит в систему с помощью логина/пароля или регистрируется в системе при получении invite-ссылки, его отправляет на `/info`, хотя должно отправлять на "/" (home page, т.е. `/main`). Это странно, поскольку редирект на `/info` должен работать только для гостей.

## Найденная причина

Проверено: это не сложная каскадная логика редиректов в `router/index.js` (там гостевая логика и так уже корректно пропускает `/main`), а буквально две прямые ошибки в коде экранов:

* `src/views/LoginView.vue`, функция `redirectToHome()` (строка ~171):
  ```js
  async function redirectToHome() {
    await router.push('/info')
  }
  ```
  Функция называется "redirectToHome", но ведёт на `/info`. Вызывается как при обнаружении уже активной сессии в `onMounted()`, так и после успешного `handleLogin()`.

* `src/views/WelcomeView.vue`, обработчик успешного авто-логина после регистрации (строка ~223):
  ```js
  await setAuthItem('sre_user_registered', 'true');
  await router.push('/info')
  ```

Похоже, это исторически осталось от более раннего варианта логики (когда, возможно, `/info` временно использовался как домашняя страница), и с тех пор не было замечено.

## Что нужно сделать

* В `LoginView.vue` — переименовать/исправить `redirectToHome()` так, чтобы она вела на `/main` (или на `/`, которая уже редиректит на `/main`, см. `router/index.js`).
* В `WelcomeView.vue` — заменить `router.push('/info')` после успешного авто-логина на `router.push('/main')`.
* Дополнительно перепроверить весь `router.beforeEach` в `router/index.js` на предмет других сомнительных/каскадных редиректов (пункт из исходного запроса — "сократить их количество, убрать каскадность"), но на первый взгляд там уже сейчас нет цепочек из нескольких последовательных редиректов — каждая ветка делает ровно один `next(...)`.

## Definition of Done

* После успешного входа по логину/паролю пользователь попадает на `/main`, а не на `/info`.
* После успешной регистрации по invite-ссылке и авто-логина пользователь попадает на `/main`, а не на `/info`.
* Переход на `/info` остаётся доступен только через явную ссылку в меню и для гостей без активной сессии (как и раньше).
* Ручная проверка: логин существующего пользователя, регистрация нового пользователя по invite, гость без сессии сканирует браслет (должен по-прежнему попадать на `/info`).
