# Minor

- **Отсутствие автотестов на регрессию.** Оба дефекта (`LoginView.vue:172`,
  `WelcomeView.vue:223`) — это буквально инвертированные строковые литералы,
  которые не были бы замечены статическим анализом или типами и могли бы
  вернуться при будущем рефакторинге незамеченными. Ручная проверка по 4
  сценариям, заявленная в плане как обязательная, по отчёту разработчика
  **не была выполнена** («Ручная проверка в браузере... не выполнялась в
  рамках этой сессии»). Сама правка тривиальна и по коду корректна (см.
  ниже), но задача была явно определена как bug fix с DoD, включающим ручную
  проверку конкретных сценариев — это стоит закрыть перед мержем, а не
  полагаться только на `npm run build`.
- Функция `redirectToHome()` в `LoginView.vue` теперь ведёт на `/main`
  жёстко закодированным путём вместо `/` (который через `redirect: '/main'`
  в `router/index.js:38-40` эквивалентен). Осознанный выбор, обоснованный в
  плане («не полагаться на цепочку redirect»); не является проблемой, но
  создаёт неявную дублирующую зависимость: если целевая домашняя страница
  когда-либо снова изменится, значение `/main` придётся синхронизировать в
  трёх местах (`router/index.js` redirect, `LoginView.vue`, `WelcomeView.vue`,
  плюс `App.vue:385` уже использует `/main` напрямую) — технический долг
  низкого приоритета, не требующий действий сейчас.

# Архитектурные замечания

- Изменение точечное и не затрагивает `router.beforeEach` — соответствует
  утверждённому плану. Прослежена логика guard'а (`router/index.js:156-261`)
  для обоих исправленных сценариев:
  - Активная сессия + прямой заход на `/login` (`meta.public: true`) → guard
    пропускает через `if (to.meta.public) return next()` (строка 204-206) →
    `LoginView.onMounted()` обнаруживает сессию → `redirectToHome()` → теперь
    корректно `/main`.
  - Авто-логин после `invite-accept` в `WelcomeView.vue` → после успешного
    `signInWithPassword` push на `/main` → guard пропускает (`/main` имеет
    `requiresAuth: false`, `meta.public` не задан) → остаётся на `/main`.
  Оба пути подтверждены чтением кода, поведение соответствует ожиданиям
  тикета.
- Гостевая ветка guard'а (строки 181-192) и явные ссылки на `/info`
  (`App.vue:91`, `MainView.vue:218`) не затронуты и не пересекаются с
  изменённым кодом — подтверждено `grep`.

# Рекомендации

- Перед закрытием тикета выполнить хотя бы вход по логину/паролю (сценарий
  1 из DoD) вручную в `npm run dev`, поскольку это прямое поведение,
  наблюдаемое пользователем, а разработчик явно пометил ручную проверку как
  невыполненную.
- Рассмотреть (вне рамок этого тикета) добавление минимального e2e/smoke
  теста на редиректы после логина/регистрации — риск, отмеченный самим
  разработчиком в разделе «Риски» плана, всё ещё актуален и подвержен
  такому же классу дефектов (инвертированный литерал) в будущем.
