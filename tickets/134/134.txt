# Тикет 134: Экраны Checkpoint — List + Bus + Group (реальные)

Часть фазы реализации Checkpoint — см. `tickets/131/MIGRATION_PLAN.md`.
По итогам архитектурного ревью (`tickets/131/MIGRATION_PLAN_REVIEW_RESPONSE.md`,
п.1, п.14) объединяет то, что в первой версии плана было тремя тикетами
(137/138/139) — List/Bus/Group однородны, прямые аналоги старых экранов,
и не нужно временное состояние «4-я кнопка рядом со старыми тремя» — при
отсутствии живых пользователей эти экраны разрабатываются и проверяются
прямым переходом по маршруту, без правки `MainView.vue`. Единственная
правка `MainView.vue` (замена трёх старых кнопок на одну «Checkpoints») —
в тикете 137, один раз.

## Цель

Перенести `CheckpointListPrototypeView.vue`, `CheckpointBusPrototypeView.vue`,
`CheckpointGroupPrototypeView.vue` на реальные данные: список/история
точек за день с явным созданием, детальный мониторинг Bus-точки (по
автобусам), детальный мониторинг Group-точки (по группам, со
сворачиванием «чистых» групп).

## Что прочитать перед началом

- `src/views/CheckpointListPrototypeView.vue`,
  `CheckpointBusPrototypeView.vue`, `CheckpointGroupPrototypeView.vue` —
  эталонная раскладка и логика всех трёх экранов.
- `src/components/checkpoints-prototype/CheckpointCreateModal.vue`,
  `CheckpointStatusBadge.vue`, `CheckpointTypeBadge.vue`,
  `CheckpointOriginBadge.vue` — переиспользуемые компоненты (бейдж
  «Admin» vs «Auto (Betreuer X)» обязателен, `131.txt`, «Открытые
  вопросы»).
- `src/composables/useCheckpoints.js` (тикет 133, должен быть готов) —
  реальный источник данных вместо мока: `summarizeCheckpoint`,
  `checkpointHasOpenIssues`, `getBusChildrenBreakdown`, `getBusDelta`,
  `getGroupChildrenBreakdown`, `getGroupDelta`, `getCheckpointBetreuerList`.
- `tickets/130/decision.md`, пп. 3, 6 — несколько одновременно открытых
  точек разных типов — нормальное состояние, не показывать как ошибку;
  две открытые одного типа — аномалия, показывать как таковую, если
  встретилась.
- `src/views/AdminBusView.vue:102-186`, `src/components/BusDetailModal.vue:105-125`
  — исходная таблица автобусов и логика списка пакетов, источник вёрстки
  (не для копирования логики — та завязана на `children_today`, здесь
  используются `scan_packets`/`scans` через `checkpoint_id`). Файлы
  читаются только как референс — сами удаляются в тикете 137.
- `src/views/ChildrenView.vue:75-135`, `src/components/GroupDetailModal.vue`
  — то же самое для групп (`130.txt:225-227` — логика сворачивания
  «чистых» групп уже реализована в прототипе, в `ChildrenView.vue` её не
  было).
- `src/composables/useGroups.js`, `fetchGroupDetails()` — уже возвращает
  детей с `presenceNow`/`presenceToday`; оценить, что переиспользуется
  как есть, а что заменяется на подсчёт через `checkpoint_id` (тикет 133
  уже решил это в `getGroupChildrenBreakdown`/`getGroupDelta` — этот
  тикет использует готовый результат, не пересматривает).
- `tickets/131/IMPLEMENTATION_PLAN.md`, раздел «UI изменения» — примерные
  маршруты (`/admin/checkpoints`, `/admin/checkpoints/list` и т.д.) —
  пример, финализировать по месту.

## Затрагиваемые части проекта

`src/views/`, `src/router/index.js`. `MainView.vue` в этом тикете **не
меняется** (см. заголовок).

## Файлы/подсистемы, которые будут изменены

- Новые файлы `src/views/CheckpointListView.vue`, `CheckpointBusView.vue`,
  `CheckpointGroupView.vue` (копии `*PrototypeView.vue` без суффикса
  `Prototype`, без `DebugTag`/`Page N`/`elN` — были нужны только для
  UX-согласования 130_2).
- `src/router/index.js` — новые маршруты (например `/admin/checkpoints`,
  `/admin/checkpoints/bus/:id`, `/admin/checkpoints/group/:id`), без
  удаления `-prototype`-маршрутов (остаются до тикета 137).

## Что должно быть реализовано

1. `CheckpointListView.vue`: список/история точек текущего дня через
   `useCheckpoints.fetchCheckpointsForDay(day)` + Realtime-подписка, без
   кнопки «Aktualisieren». Явное создание через `CheckpointCreateModal` →
   `createCheckpoint(type)`, обработка `{error: 'ALREADY_OPEN',
   existingId}`. Клик по строке → переход в `CheckpointBusView.vue`/
   `CheckpointGroupView.vue`/маршрут Lazy (тикет 135) по `checkpoint.type`.
   Бейдж «создана автоматически (Betreuer X)» / «создана администратором»
   — обязателен на каждой строке.
2. `CheckpointBusView.vue`: заголовок (`summarizeCheckpoint`, сравнение с
   `baseline_children_count`), таблица автобусов (`config.total_buses`)
   с количеством детей/Betreuer/списком пакетов раунда, `getBusDelta` для
   сравнения с утренней точкой. Кнопки Finish (с предупреждением при
   `checkpointHasOpenIssues`)/Reopen/Remove (с подтверждением,
   необратимо). Realtime, без «Aktualisieren». Ссылки на карточки детей/
   Betreuer через `ChildLink`/`BetreuerLink` (тикет 133).
3. `CheckpointGroupView.vue`: заголовок (аналогично), список групп
   (`config.total_groups`) — статус-индикатор, Morgen/Aktuell (подсчёт по
   `checkpoint_id`, не `groups_today`), Betreuer, `Differenz`, список
   недостающих детей по клику/разворачиванию, сворачивание групп без
   проблем. Finish/Reopen/Remove — идентично Bus. Realtime. Ссылки через
   `ChildLink`/`GroupLink`.

## Что не входит

- Экран Lazy — тикет 135 (независим).
- Замена `/admin-busses`/`/children`, правка `MainView.vue` — тикет 137.
- Изменение `ScannerBusView.vue`/`ScannerGroupView.vue` — не входит ни в
  один тикет этой фазы.
- `BusDetailModal.vue`/`GroupDetailModal.vue`/`AdminBusView.vue`/
  `ChildrenView.vue` не удаляются в этом тикете — тикет 137.

## Результат выполнения тикета

- Все три экрана работают на реальных данных, доступны по новым
  маршрутам (прямым переходом, кнопки входа пока нет — см. заголовок).
- `npm run build` проходит без ошибок.
- Ручная проверка на устройстве: авто-создание Bus/Group-точки по первому
  пакету (после 132), Finish/Reopen/Remove на реальной БД, Realtime-
  обновление без ручного действия.

## Зависимости

Требует 133. Независим от 135, 136. Блокирует 137.
