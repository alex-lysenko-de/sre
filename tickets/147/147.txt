Задача
======

Исправить рассинхронизацию между документом
`vault/02-Предметная-область/Checkpoint.md` и фактической реализацией
Checkpoint (`useCheckpoints.js`): "fehlend"/"missing" во всех детальных
экранах перекличек сейчас считается относительно **полного списка всех
когда-либо зарегистрированных детей** (`Roster`), а должно считаться
относительно **presentRoster** — списка детей, зафиксированного по
первой за день завершённой контрольной точке.

Формула (от заказчика):

    n = roster - checkedRoster            # не нужно вообще
    missingRoster = presentRoster - checkedRoster   # нужно это

Даже в первой перекличке дня информация об отсутствующих не нужна —
пока presentRoster не зафиксирован, "fehlend" не имеет смысла. Во всех
последующих перекличках "fehlend" должен означать "кого не хватает по
сравнению с тем, кто был сегодня утром" (кого искать), а не "кто вообще
не пришёл сегодня" (это никого не интересует).

Дополнительные требования
--------------------------

1. **Где хранить presentRoster.** Заказчик предложил рассмотреть
   `children_today`. Нужно решить, годится ли эта таблица, или нужно
   другое решение — с обоснованием.

2. **Подтверждение фиксации Baseline.** При закрытии контрольной точки,
   которая становится первой завершённой за день (фиксирующей
   presentRoster), администратор должен увидеть подсказку на немецком,
   спрашивающую, фиксировать ли текущий список присутствующих как
   дневную референсную точку. Согласованный текст:

       "Soll die aktuelle Liste der anwesenden Kinder als
       Tagesreferenz festgehalten werden?"

   Отказ не должен блокировать закрытие самой точки — точка закрывается
   как обычно, просто без Baseline. Должна быть отдельная кнопка,
   доступная на любой уже закрытой точке дня, пока Baseline ещё не
   зафиксирован — "зафиксировать сейчас" (не только на первой
   хронологически точке).

3. **Целевая платформа — мобильный экран.** Приложение используется
   только на телефонах (в основном iPhone). Отметить в `CLAUDE.md`
   iPhone 12 как целевой экран для дизайна.

Ограничение по объёму на данном этапе
--------------------------------------

Тикет создаётся на этапе **планирования**: нужен только согласованный
`IMPLEMENTATION_PLAN.md`, доступный для правок автором задачи, прежде
чем передавать его разработчику для реализации. Код (`src/`, `doc/db/`,
`vault/`, `CLAUDE.md`) в рамках этой сессии **не меняется**.
