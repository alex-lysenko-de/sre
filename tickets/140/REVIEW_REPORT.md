# Minor

1. **`CheckpointOriginBadge`/`CheckpointStatusBadge` внутри `.cp-item-body`
   в `CheckpointListView.vue` — риск CSS-каскада для закрытых карточек.**
   До 140 бейджи создателя/статуса лежали в `.cp-item-footer` (без
   переопределения цвета). Теперь `<div class="cp-item-line">` со
   `CheckpointOriginBadge`/`CheckpointStatusBadge` вложены в
   `.cp-item-body`, у которого для закрытых карточек действует правило
   `.cp-item-card-closed .cp-item-body { color: #868e96; }`
   (`CheckpointListView.vue:306-308`). Специфичность этого правила
   (2 класса + `data-v-*` атрибут родительского scoped-стиля) равна или
   выше специфичности собственных scoped-правил дочерних компонентов
   (`.cp-origin-line`, `.cp-status-text-open/finished` — по одному классу
   + свой `data-v-*`), поэтому для закрытых checkpoint'ов текст
   "Ersteller"/"Status" визуально получит унаследованный приглушённый
   серый вместо цветов, заданных в самих `CheckpointOriginBadge.vue`/
   `CheckpointStatusBadge.vue` (зелёный "Offen" там неактуален, т.к.
   Offen у закрытых не бывает, но `Geschlossen`/имя автора могут
   отрисоваться не тем оттенком, что задумано в компоненте). Требование
   тикета ("заметность результата должна сохраняться для закрытых
   перекличек") касалось именно `cp-item-result` — он **вне**
   `.cp-item-body` и корректно не тускнеет; для Ersteller/Status это не
   требование, а побочный эффект переноса блоков внутрь контейнера с
   имевшимся ранее правилом приглушения, о котором нет упоминания в
   плане/отчёте. Не блокирует приёмку, т.к. визуально не критично
   (текст читаем, просто чуть темнее задуманного), но стоит проверить на
   устройстве при следующей device-проверке.

2. **`ArmbandView.vue` — заголовок с ID, задокументированный в плане/
   отчёте 140, уже не соответствует текущему состоянию файла.**
   `IMPLEMENTATION_PLAN.md`/`IMPLEMENTATION_REPORT.md` фиксируют решение
   "заголовок → `📍 Armband‑Zuordnung (ID={{ bandId }})`" — так и было
   сделано в `955751a`. Однако более поздний, не связанный с тикетом 140
   коммит `7f683de "small UI fixes"` (2026‑08‑04) откатил это изменение
   в заголовке и вместо этого перенёс ID в абзац ниже
   (`Dieses Armband (ID=<strong>{{ bandId }}</strong>) ist noch keinem
   Kind zugeordnet.`). Само требование тикета 140 (ID браслета должен
   быть явно виден) по-прежнему выполняется — это ровно второй из двух
   вариантов, предложенных в `140.txt`, — поэтому это не дефект
   реализации 140. Но `IMPLEMENTATION_REPORT.md` тикета 140 теперь
   описывает состояние кода, которого в HEAD уже нет (документация
   разошлась с кодом из-за стороннего коммита) — стоит поправить формулировку
   в отчёте или явно сослаться на `7f683de`, чтобы не вводить в
   заблуждение при будущем чтении истории тикета.

# Архитектурные замечания

- Оба новых текстовых блока (`cp-origin-line`, `cp-status-line`)
  дублируют один и тот же hardcoded цвет `#495057` в двух разных
  scoped-стилях компонентов вместо общей переменной/класса. Это
  соответствует уже принятому в проекте стилю (hardcoded HEX-цвета
  используются повсеместно, общих CSS-переменных в проекте нет), так что
  не является новым нарушением, только фиксирую как потенциальный
  технический долг наравне с остальным кодом checkpoints-компонентов.
- Прежний текст `Auto (<BetreuerLink/>)` для не-админов несла лёгкий
  дополнительный смысл ("создано автоматически", в противовес явному
  созданию) помимо самого имени. После правки строка стала одинаковой
  для явного/авто-создания ("Ersteller: <b>Имя</b>") — по 140.txt это
  ровно то, что требовалось (`Создатель: <b>{имя}</b>` без дополнительных
  пометок), так что не дефект, но стоит иметь в виду, что различие
  auto/explicit создания теперь нигде в UI не отображается (раньше хоть
  как-то отражалось словом "Auto").
