# Реализованные изменения

Реализовано строго по `IMPLEMENTATION_PLAN.md` (план "2 слоя", зафиксированный в `DECISIONS.md` по итогам ревью архитектуры):

1. **`ScannerView.vue` (боевой `/scanner`) не тронут ни в одной строке** — подтверждено `git status --short src/` (файл не входит в список изменённых/новых).

2. **`useScannerFeedback.js`** — написан заново (не перенесён из `ScannerView.vue`), содержит только технические примитивы (`AudioContext`, `playTone`, `navigator.vibrate`), без знания о доменных исходах "успех"/"ошибка".

3. **`Scanner.vue`** — покрывает пункты 1-3, 7 тикета 116.txt целиком и базовую часть пунктов 4-6:
   - Пункт 1: выбранная камера сохраняется в `localStorage` и используется при следующей инициализации (`initScanner()`, аналогично механике `ScannerView.vue`, но реализовано независимо).
   - Пункт 2: индикатор `currentCameraLabel` вместо статус-бейджа "Scanner aktiv"; кнопка "Automatisch (Rückkamera)" доступна для возврата в любой момент (не блокируется после ручного выбора камеры, как было в старом сканере) — при нажатии дополнительно очищает сохранённое предпочтение в `localStorage`, чтобы следующий запуск тоже стартовал автоматически.
   - Пункт 3: фронтальные камеры видны в общем списке (`Html5Qrcode.getCameras()` не фильтрует по типу — как и в 103); раскладка — область сканирования (`.proto-scan-area`, `flex: 1 1 auto`) вверху, ничего не отображается над ней.
   - Пункт 7: все элементы управления (индикатор камеры, кнопки выбора/автоматического режима, выпадающий список камер) — в нижнем блоке `.proto-scanner-controls`.
   - Пункты 4-6 (базовая часть): при каждом успешном сыром декоде — `pause(true)`, нейтральный сигнал "scan" + короткая вибрация, независимо от дальнейшей бизнес-логики (реализует явное требование 116.txt: "звук всегда при успешном считывании, вне зависимости от бизнес-логики"). Далее резолв (невалидный формат / браслет не найден / ребёнок найден) — свой сигнал и вибрация для каждого исхода (таблица сигналов плана), полноэкранный (в рамках области сканирования) цветной экран подтверждения (~0.8 с, в диапазоне 0.5-1 с из требования), после чего `resume()`.
   - Результат резолва передаётся наверх через `onChildResolved(result)` (обязательный проп); ожидаемый `{ title, subtitle, variant? }` используется для текста/цвета экрана подтверждения — по умолчанию (`defaultDisplayFor`) для `invalid`/`not-found`/`found`, с возможностью переопределения слоем 2.
   - `recordChildPresence()` не импортируется и не вызывается нигде в файле.

4. **`ScannerPrototypeView.vue`** — покрывает верхний уровень:
   - Дедупликация "в рамках захода": если `child.id` уже есть в собранном пакете — воспроизводится дополнительный сигнал "duplicate" + короткая вибрация (поверх уже воспроизведённого `Scanner.vue` сигнала "success", как и предписано планом: "слой 2 может добавить дополнительный сигнал... не вместо"), возвращается `{ title: 'Bereits gescannt', subtitle: <имя>, variant: 'error' }`, элемент не добавляется в пакет повторно.
   - Сборка пакета: `type: 'GROUP'`, `author_id: userStore.userInfo.id`, `group_id: userStore.userInfo.group_id`, `started_at` фиксируется при первом успешном не-дублирующемся резолве, `finished_at` обновляется на каждый скан (и дополнительно фиксируется при нажатии "Senden").
   - "Senden" — заглушка: только устанавливает `finished_at` и локальное сообщение `sentMessage`, не выполняет `fetch`/Supabase-вызовов.
   - "Beenden" — останавливает сканер (`scannerRef.value.stop()`) и возвращает на `/main`.

5. **Роутер + меню** — новый маршрут `/scanner-prototype` рядом с `/scanner`; новая кнопка в `MainView.vue` с подписью "Scannen (Neu, Prototyp)", явно отличающей её от существующей кнопки "Scannen", видна при том же условии (`isAuthenticated`), не заменяет и не скрывает существующую кнопку.

Иконки Font Awesome: для экрана подтверждения и индикатора камеры использованы только уже зарегистрированные в `main.js` иконки (`faCheckCircle`, `faTimes`) — `main.js` не менялся, чтобы не расширять список зависимостей сверх необходимого (иконка "times" вместо "times-circle" для красного экрана, простой текст без иконки для индикатора камеры).

  - поведение `pause(true)`/`resume()` из `html5-qrcode` на реальных устройствах (риск, явно отмеченный в плане как непроверенный на этапе архитектуры).
