# Цель

На экране "Armband-Zuordnung" (`ArmbandView.vue`, route `/armband/:id`)
разбить однострочное представление ребёнка в списке "Kind auswählen"
(`{{ child.name }} ({{ child.age }} J) — Armband: {{ child.band_id ?? '—' }}`)
на несколько отдельных строк (имя / возраст / ID браслета), чтобы список
оставался читаемым на узком экране телефона во время сканирования.
Radio-выбор (`v-model="selectedChildId"`) и логика привязки
(`assignArmband()`) не меняются — правка чисто вёрсточная, в пределах
одного `<label class="form-check-label">`.

# Анализ текущей архитектуры

`ArmbandView.vue` — самостоятельный view-компонент без вложенных
дочерних компонентов и без Pinia-стора для списка детей: список грузится
напрямую через `composables/useArmband` (`getChildrenByGroup(groupId)`)
в локальный `ref children`, рендерится `v-for` по `<li class="list-group-item">`
c Bootstrap `.form-check`/`.form-check-input`/`.form-check-label`.
Стилизация — `<style scoped>` внутри самого файла, отдельного
CSS-модуля/дизайн-системы для этого списка нет.

В проекте нет переиспользуемого компонента "список детей с выбором" —
похожий по смыслу `SelectChildView.vue` (`/select-child`) реализует
собственную независимую вёрстку (`.children-list`/`.child-item`) под
свой контекст (карточка на всю страницу, поиск, multi-select, swim-badge)
и не используется и не должен быть использован здесь: это отдельный,
более тяжёлый компонент с другим API (`props`/`emits`), а не
переиспользуемый пункт списка. Прецедент показывает лишь общий стиль
(Bootstrap `.form-check`, `<strong>` для имени, `<small>`/`.text-muted`
для второстепенных полей) — само разбиение на компонент не требуется и
не предполагается заданием.

Вывод: контекст локальный и самодостаточный, изменения не выходят за
пределы `ArmbandView.vue`.

# Затрагиваемые модули

* `src/views/ArmbandView.vue` — единственный затрагиваемый файл.

Никакие другие view/компоненты/composables/stores не читают и не
переиспользуют разметку этого списка — не затрагиваются.

# Изменения существующих компонентов

`src/views/ArmbandView.vue`:

* Внутри `<label class="form-check-label" :for="'child-' + child.id">`
  (строки 56-59) заменить однострочный текст на блочную разметку из
  нескольких строк — например:
  ```html
  <label class="form-check-label" :for="'child-' + child.id">
    <div class="child-name">{{ child.name }}</div>
    <div class="child-meta">Alter: {{ child.age }}</div>
    <div class="child-meta">Armband Id: {{ child.band_id ?? '—' }}</div>
  </label>
  ```
  (конкретные CSS-классы/теги — на усмотрение реализации; главное —
  каждое поле в собственном блочном элементе, а не в одной строке через
  тире/скобки).
* В `<style scoped>` добавить минимальные классы для нового блока
  (например, `.child-name` — жирный/крупнее, `.child-meta` — обычный
  текст/`text-muted`, небольшой `margin-bottom` между строками), без
  переработки остального стиля файла.
* `v-model="selectedChildId"`, `:value="child.id"`, `:id="'child-' + child.id"`,
  `v-for="child in children"` — не меняются.
* Остальная разметка файла (Ladezustand/Fehlerzustand/Aktionstasten/
  скрипт) — не затрагивается.

# UI изменения

* Список "Kind auswählen" в `ArmbandView.vue`: каждый пункт вместо одной
  строки `Имя (Возраст J) — Armband: ID` показывает три отдельные
  строки: имя, `Alter: <возраст>`, `Armband Id: <id или —>`.
  Пример из тикета:
  ```
  Max Mustermann
  Alter: 10
  Armband Id: 104
  ```
* Radio-кнопка остаётся слева от текста (стандартное поведение
  Bootstrap `.form-check` с многострочным `.form-check-label`), клик по
  любой из трёх строк по-прежнему выбирает соответствующего ребёнка
  (штатное поведение `<label for="...">`, не требует дополнительного
  кода).
* Высота каждого `<li class="list-group-item">` увеличится (три строки
  вместо одной) — список станет длиннее по вертикали; отдельного
  скролл-контейнера сейчас нет и не требуется по критериям приёмки —
  поведение прокрутки страницы не меняется.

# План реализации

1. В `src/views/ArmbandView.vue` заменить содержимое `.form-check-label`
   (строки 56-59) на блочную многострочную разметку (имя / `Alter: N` /
   `Armband Id: X`).
2. Добавить в `<style scoped>` минимальные классы для новых блочных
   элементов (отступы между строками, акцент на имени).
3. Проверить в узком viewport (DevTools mobile emulation, ширина
   ~360-390px) и/или на реальном устройстве, что:
   * строки не переносятся браузером произвольно;
   * клик/тап по любой строке пункта по-прежнему выбирает radio;
   * список остаётся читаемым при разных длинах имени.
4. Пройти сценарий целиком: выбрать ребёнка → "Armband zuordnen" →
   убедиться, что привязка и переход на `ChildDetail` работают как
   раньше (логика `assignArmband()` не менялась, но сценарий необходимо
   пройти вручную, так как автотестов на этот экран в проекте нет).
5. `npm run build` — убедиться, что сборка проходит без ошибок/warning
   по изменённому файлу.

Порядок жёсткий только в части "сначала разметка/стили, затем ручная
проверка" — шаги 1-2 являются одной логической правкой.

# Риски

* **Низкий, вёрсточный**: удлинение каждого пункта списка (1 строка →
  3 строки) может потребовать больше вертикальной прокрутки при
  большой группе — некритично, так как список и раньше был
  прокручиваемой частью страницы, отдельного ограничения высоты
  (`max-height`/`overflow`) для `.list-group` в текущем коде нет.
* **Низкий**: длинные имена детей при узкой ширине экрана всё ещё могут
  переноситься внутри строки имени (перенос слова — приемлем и ожидаем
  согласно тексту тикета, критично только избавиться от переноса
  *всей* строки "имя+возраст+ID" как единого блока).
* Риска для логики выбора/привязки нет — `v-model`, `:value`, обработчики
  кликов не трогаются, значит поведение radio-выбора и `assignArmband()`
  гарантированно не регрессирует.
* Так как автоматических тестов для этого экрана нет, единственная
  проверка регрессии — ручная (шаг 4 плана реализации); стоит явно
  выполнить её перед переводом тикета в `REVIEW`.

# Definition of Done

* В `ArmbandView.vue` каждый пункт списка "Kind auswählen" показывает
  имя, возраст (`Alter: N`) и ID браслета (`Armband Id: X`) на трёх
  отдельных строках вместо одной строки через тире/скобки.
* Выбор ребёнка (radio, `v-model="selectedChildId"`) и последующая
  привязка браслета (`assignArmband()` → переход на `ChildDetail`)
  работают без изменений, как до правки.
* Список остаётся читаемым в узком viewport (проверено в DevTools
  mobile emulation и/или на реальном устройстве).
* `npm run build` проходит без ошибок.
* Правка ограничена файлом `src/views/ArmbandView.vue` — никакие
  другие компоненты/composables/stores/БД/API не затронуты.
