## Чек-лист сквозной проверки на устройстве (для пользователя)

Взято из `139.txt` п.1 дословно, разбито на выполнимые шаги. Результат
каждого пункта нужно вписать в `IMPLEMENTATION_REPORT.md` (пройдено/нет,
что увидено):

1. Открыть `/admin/checkpoints` под админом, у воспитателя отправить первый
   BUS-пакет — точка BUS должна появиться в списке автоматически, без
   действий администратора, воспитатель не должен увидеть ошибку.
2. То же для GROUP и LAZY (первый пакет каждого типа создаёт свою точку).
3. Пока BUS открыта, отправить первый GROUP-пакет — обе точки должны быть
   видны одновременно открытыми, без конфликта.
4. В `CheckpointListView.vue` нажать «создать» для типа, у которого уже
   есть открытая точка — должно быть отклонено с понятной ошибкой
   (`ALREADY_OPEN`), не тихим сбоем.
5. Нажать Finish на первой за день точке (любого типа) — проверить, что
   `baseline_children_count` зафиксирован (виден в деталях точки).
6. Reopen только что завершённой точки — статус возвращается в OPEN;
   попробовать Reopen, когда уже есть другая открытая точка того же типа —
   должно быть отклонено.
7. Remove точки — убедиться, что она пропадает из списка/истории; повторно
   отправить (или дождаться повтора) тот же офлайн-пакет с воспитательского
   устройства — должен быть принят как новый (не задедуплицирован).
8. На всех трёх детальных экранах (Bus/Group/Lazy) — открыть на двух
   устройствах одновременно, отправить пакет с третьего — оба экрана
   обновляются сами, без нажатия «Aktualisieren».
9. В списке точек — визуально отличить точку, созданную первым пакетом
   воспитателя (авто), от точки, созданной кнопкой администратора
   (явно) — подпись/бейдж должен быть виден.
10. Смена дня: дождаться (или симулировать переводом времени) полуночи;
    убедиться, что вчерашняя зависшая `OPEN`-точка не мешает создать
    сегодняшнюю точку того же типа первым пакетом.
11. `ChildDetailView.vue` → «Präsenz registrieren» → ребёнок должен
    появиться в соответствующем Checkpoint-экране (тикет 136).
12. Убедиться, что `/admin-busses`, `/children`, `/headcount`,
    `/admin/checkpoints-prototype*` не открываются (маршруты отсутствуют,
    не просто скрыты) — прямой переход по URL должен не найти маршрут, а
    не показать пустой/сломанный экран.
