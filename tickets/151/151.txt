# Ticket 151. Объединить дублирующие экраны просмотра ребёнка в один + унифицировать навигацию/кнопки

## Описание проблемы

В проекте есть два почти идентичных по назначению экрана "просмотр
карточки ребёнка":

* **`ChildDetailView.vue`** (route `/child/:id`, name `ChildDetail`) —
  общий экран просмотра ребёнка, на него ведут `ArmbandView.vue`
  (после привязки браслета), `ChildEditView.vue` (после сохранения),
  `GroupEditView.vue` (клик по строке ребёнка в списке группы).
* **`ChildCardView.vue`** (route `/admin/checkpoints/child/:id`, name
  `CheckpointChildCard`) — экран просмотра ребёнка в разделе
  Checkpoint/перекличка, на него ведут ссылки из чекпоинт-экранов.

Оба показывают практически одну и ту же информацию (возраст, группа,
Schwimmabzeichen, Armband, заметки), но по-разному:

* `ChildCardView.vue` уже содержит историю сканов ребёнка (данные из
  таблицы `scans`, через `useChildren().fetchChildDetailsAndScans()`)
  и уже оформлен в стиле `CheckpointBusView.vue` (компактная круглая
  кнопка "назад" вверху слева, `router.back()`), но **не имеет кнопки
  "Entfernen"** (удалить ребёнка) вообще.
* `ChildDetailView.vue` истории сканов не показывает (только баннер
  "анвесенд сегодня/нет" через отдельные запросы
  `isChildPresentToday()`/`getChildBusForToday()`), зато имеет кнопки
  "Bearbeiten"/"Entfernen" — но:
  * кнопка "Zurück" всегда ведёт на жёстко заданный `/main`
    (`function goBack() { router.push('/main') }`), а не туда, откуда
    пользователь реально пришёл (обычно это список детей группы —
    `/group-edit`);
  * кнопки узкие, расположены плотно друг к другу — легко промахнуться
    пальцем на телефоне.

Само по себе смешивание информации о ребенке и списка checkpoints противоречит принципу single responsibility а также заявленому в \vault\02-Предметная-область\Checkpoint.md "принципы интерфейса":
"""
1. Каждая сущность имеет собственный экран — избегать экранов «смешанного
   назначения».
"""

Также проверено: `fetchChildDetailsAndScans()` (источник истории
сканов для `ChildCardView.vue`) сейчас запрашивает **все** сканы
ребёнка без фильтра по дате (только `limit(50)`, сортировка по
`created_at desc`) — то есть показывает историю за всё время, а не
только за сегодня.



## Требуется

### 1. Изменить внешний вид ChildDetailView.vue  (маршрут — `/child/:id`)
За основу взять внешний вид `ChildCardView.vue` (у него уже нужный стиль для текста и кнопок)
Изменить стиль текста, стиль и расположение кнопок на странице ChildDetailView.vue
А именно:

* кнопка "Zurück" — компактная круглая иконка-кнопка вверху слева
  (как `.cp-back-btn` в `CheckpointBusView.vue`), а не широкая кнопка
  на всю ширину;
* остальные кнопки действий ("Bearbeiten" и т.п.) — увеличить отступы
  между ними и паддинги самих кнопок, чтобы было проще попасть по ним
  пальцем;
* кнопка **"Entfernen" — исключение**: она должна оставаться
  маленькой/компактной (как `.cp-remove-btn` в `CheckpointBusView.vue`)
  умышленно, чтобы снизить риск случайного нажатия. В объединённом
  экране такой кнопки сейчас нет (у `ChildCardView.vue` её вообще нет)
  — её нужно добавить, переиспользовав существующую логику удаления
  из `ChildDetailView.vue` (`deleteChild()` + подтверждение через
  `confirm()`).

сразу под баннером "анвесенд сегодня" (`presenceInfo` в текущем
`ChildDetailView.vue`), Добавить кнопку "checkpoints list" которая открывает страницу `/admin/checkpoints/child/:id`
Таким образом пользователю логично предлагается просмотреть историю отметок присутствующего сегодня ребенка.
кнопка  не видна для простых пользователей. Доступна только для admin 

 
### 2. изменить страницу ChildCardView.vue (маршрут `/admin/checkpoints/child/:id`)
по замыслу страница должна отображать только список checkpoints для выбранного ребенка за текущий день
Поэтому надо убрать всю лишнюю детельную информацию о ребенке. Оставить только заголовок, кнопку "Zurück" и список checkpoints
В истории сканов должны отображаться только записи, сделанные сегодня
(`scans.date`, `character varying`, формат `YYYY-MM-DD`, как и в
других date-scoped таблицах проекта — `children_today`, `checkpoints`,
`scan_packets`) — а не последние 50 записей за всё время.

### 3. Подправить ссылки
по идее все страницы на '/admin/checkpoints' имеющие сейчас ссылку на `/admin/checkpoints/child/:id`
на самом деле должны открывать страницу `/child/:id` и показывать детальную информацию о ребенке.
Находясь на странице `/child/:id` пользователь всегда может перейти на `/admin/checkpoints/child/:id`


### 3. Кнопка "Zurück" должна возвращать на предыдущий экран
По возможности — на тот экран, с которого пользователь реально пришёл, а не на жёстко заданный маршрут.
`ChildCardView.vue` уже делает это правильно (`router.back()`) 
Это касается всех страниц с кнопкой "Zurück"
Такое же поведение должно быть для ChildDetailView.vue 



## Критерии приемки


* все существующие точки входа (`ArmbandView`, `ChildEditView`,
  `GroupEditView`, чекпоинт-экраны)  корректно открывают
  экран ребёнка на `/child/:id`
* находясь на экране ребенка админ всегда может просмотреть список ScanEvent за текущий день. используя ссылку на страницу /admin/checkpoints/child/:id

* кнопка "Zurück" возвращает на экран, с которого пользователь пришёл
  (не на жёстко заданный `/main`);
* стиль и расположение кнопок соответствуют новому дизайну:
  кнопка "Zurück" — компактная, остальные кнопки — с увеличенными
  отступами/паддингами для удобства нажатия, кроме кнопки "Entfernen",
  которая остаётся маленькой;
* в истории сканов ребёнка отображаются только сегодняшние записи;
* кнопка "Entfernen" присутствует и работает (с подтверждением) в
  объединённом экране.
