# Первая регистрация дня

> Источник: `doc/info.md` (удалён в тикете 118, содержание перенесено сюда).

Перед началом поездки проводится регистрация участников (нулевая
перекличка) — определяется **Daily Roster** (`presentRoster`, см.
[[Checkpoint]], глоссарий): часть общего Roster ([[children]]), которая
участвует в сегодняшней поездке. `absentRoster = Roster − presentRoster`. В
дальнейшем список может изменяться (например, ребёнок опоздал и приехал
позже вместе с родителями). Все остальные контрольные точки ([[Checkpoint]])
проводятся только среди детей, входящих в Daily Roster текущего дня.

## Текущее состояние в схеме БД (открытая идея)

Отдельной таблицы/концепции «day participants» (список детей дня, отдельно
от общего списка `children`) **в схеме БД пока нет**. Фактическое участие
ребёнка в конкретном дне выражается косвенно — через наличие
date-scoped записи в [[children_today]] (уникальность `(child_id, date)`,
создаётся первым сканом с этой датой — см. [[Триггеры]]). Новый день
начинается сам собой с первым сканом новой даты, никакого явного «Tag
schließen»/сброса больше нет (автоматическая граница дня, см. [[Checkpoint]]).
Явного отдельного «списка участников дня» с историей по датам для детей (в
отличие от Betreuer, для которых такая история есть — см.
[[user_group_day]]) не реализовано — Daily Roster конкретного прошедшего дня
восстанавливается только косвенно, через `children_today`-записи с этой
датой.

Это отмечено как открытая идея, ранее зафиксированная в
`doc/db_children_scans_days.txt`, требующая отдельного решения вне рамок
текущей ревизии документации (тикет 108).

## Регистрация Betreuer на день

В отличие от детей, у Betreuer ежедневная регистрация участия реализована
явно — через таблицу [[user_group_day]] и обязательное модальное окно
`DailyCheckInModalView.vue` (см. [[Группы-и-рабочий-день]]).
