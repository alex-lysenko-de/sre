# Checkpoint (Контрольная точка)

> Первоисточник архитектуры — **не дублируется здесь**:
> `tickets/130/decision.md` (гибридная модель, целиком) и
> `tickets/130/IMPLEMENTATION_PLAN.md` (Aggregation Model, схема БД,
> псевдокод). Эта заметка — краткая доменная сводка + ссылки на код/схему.
> Реализована тикетами 131-138, финальная сверка — тикет 139.

Заменяет прежнюю сущность «Перекличка» (Roll Call) — та же концепция,
переименована в тикете 130. Старый механизм (Kopfzählung + `reset_events`,
кнопки «Tag starten»/«Soft Reset» в `AdminBusView.vue`) полностью удалён
(тикет 137/138) — описан в [[Переклички]] как историческая заметка, здесь
не переиспользуется.

## Три типа

| Тип | Назначение | Стратегия агрегирования |
|---|---|---|
| **BUS** | подсчёт детей по автобусам при посадке/высадке | `Union` всех пакетов (накопление, повторный скан не портит результат) |
| **GROUP** | подсчёт детей по группам, до/после передислокации | `Last Packet Wins` (каждый пакет — полная фотография группы, замена предыдущего) |
| **LAZY** | перекличка в середине дня без сбора всей группировки («появиться на базе») | `Union` всех пакетов, как BUS |

Почему GROUP отличается: во время автобусной переклички невозможно понять,
закончил ли воспитатель сканирование (может прислать частичные пакеты) —
поэтому объединение. Во время групповой переклички воспитатель видит всю
группу сразу — повторная отправка означает «предыдущий пакет содержал
ошибку», не «вот ещё несколько детей». Подробности и примеры —
`tickets/130/decision.md`, «Aggregation Strategy».

## Гибридная модель жизненного цикла

1. **Создаётся автоматически** — первый пакет своего типа/дня создаёт точку
   без участия администратора; воспитатели никогда не блокируются
   ожиданием (`submit_scan_packet()`, см. [[checkpoints]]).
2. **Завершается только явно** — администратор нажимает Finish
   (`finish_checkpoint()`); авто-завершения нет ни для одного типа, включая
   LAZY (это отменяет более раннее правило `130.txt:240` «авто-завершение
   Lazy при старте Bus/Group»).
3. **Точки разных типов независимы** — BUS и GROUP могут быть открыты
   одновременно, это штатный режим, не конфликт.
4. **Не более одной открытой точки одного типа в день** — явное создание
   при уже открытой отклоняется (`ALREADY_OPEN`); частичный уникальный
   индекс `(day, type) WHERE status = 1` в БД, см. [[checkpoints]].
5. **Reopen/Remove** — `reopen_checkpoint()` отменяет Finish,
   `remove_checkpoint()` удаляет точку целиком вместе с её пакетами
   (каскадно). Отмены отдельных уже принятых пакетов без удаления всей
   точки не существует — сознательное ограничение, см. [[checkpoints]].

## Baseline присутствия (`presentRoster`)

Замена Hard Reset (`event_type=1` в старом `reset_events`): при
**первой за день завершённой контрольной точке** (любого типа —
`finish_checkpoint()`) фиксируется `baseline_children_count`. Все
последующие точки дня отображают отклонение от этого числа, а не
пересчитывают его заново.

## Автоматическая граница дня (тикет 138)

Дня как отдельного явного действия («Tag starten»/«Tag schließen») больше
не существует. [[children_today]]/[[groups_today]] date-scoped —
уникальные ограничения на `(child_id, date)`/`(group_id, date)` вместо
единственной строки на сущность; новый день начинается сам собой с первым
скана с новой датой, никакого `pg_cron`/scheduled job нет. Заменяет весь
диапазон Reset-событий старого `reset_events` (Total/Normal/Soft), см.
[[reset_events]] (историческая).

## Экраны администратора

Единая точка входа — кнопка «Checkpoints» в `MainView.vue` (заменила
«Busse»/«Admin Übersicht», тикет 137):

- `CheckpointListView.vue` (`/admin/checkpoints`) — список/история, явное
  создание, различает точки «создана автоматически (Betreuer X)» от
  «создана администратором».
- `CheckpointBusView.vue` (`/admin/checkpoints/bus/:id`) — детали BUS-точки.
- `CheckpointGroupView.vue` (`/admin/checkpoints/group/:id`) — детали
  GROUP-точки, со сворачиванием «чистых» групп (без отклонений).
- `CheckpointLazyView.vue` (`/admin/checkpoints/lazy/:id`) — прогресс LAZY
  (кто отметился / ещё нет).

Все три детальных экрана обновляются по Realtime (`postgres_changes` на
`checkpoints`+`scan_packets`) без ручной кнопки «Aktualisieren».
Дополнительно — сущностные экраны (Child/Betreuer/Group card, тикет 133) —
см. `useBetreuerEntity`, `useChildren`.

## Код

- [[checkpoints]] — таблица, RPC, RLS.
- `useCheckpoints.js` — бизнес-логика (агрегация пакетов по стратегии
  типа, форматирование для UI).
- `useSupabaseCheckpoints.js` — чистый слой доступа к Supabase (RPC-вызовы,
  Realtime-подписка), без бизнес-логики.
- `useLazyCheckpointProgress.js` — прогресс LAZY-точки по ростеру.
- `useBetreuerEntity.js` — карточка воспитателя как отдельной сущности.
- `useScanPacket.js` (тикет 120, не изменён) — сборка/отправка пакета со
  стороны воспитателя; контракт не меняется контрольными точками.
