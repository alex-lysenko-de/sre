## Публичные vs защищённые

- `meta.public: true` — доступны без регистрации вообще (гостевой доступ,
  см. [[Модель-аутентификации]]): `Login`, `Welcome`.
- `requiresAuth: false` без `public` — `Main`, `Info`: доступны и гостям, и
  авторизованным (не редиректят на `/login`), но не входят в «гостевой
  белый список» наравне с `public`.
- `requiresAuth: true` — обязательна активная сессия + активный пользователь
  в [[users]].
- `requiresAdmin: true` — дополнительно `role === 'admin'`.

## `?id=`/`?n=` → `/armband/:id`

Проверка `to.query.id || to.query.n` стоит в самом конце `router.beforeEach`,
**после** веток `meta.public` и `meta.requiresAuth` — а обе эти ветки
возвращаются через `next(...)` раньше. Значит редирект физически достижим
только для маршрутов без `public` и без `requiresAuth: true` — по факту в
текущей карте маршрутов это ровно `/main` и `/info` (оба `requiresAuth:
false`, без `public`). Не «любой маршрут» (уточнено по итогам ревью тикета
108, `tickets/108/REVIEW_REPORT.md`, Major 4) — но именно `/main` и есть
основной сценарий: короткая QR-ссылка ведёт на `/` → редирект на `/main` →
этот блок кода выполняется. Это и есть точка входа публичного QR-URL (см.
[[QR-код-URL]]) — само приложение открывается по короткой ссылке с
параметром, а не по прямому пути `/armband/:id`.
