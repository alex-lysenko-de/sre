# `reset_events`

> **Историческая заметка (тикет 139).** Механизм ниже заменён
> [[Checkpoint]] (тикеты 130-138): точки создаются/завершаются явно
> (`checkpoints`, [[checkpoints]]), а граница дня теперь автоматическая —
> date-scoped [[children_today]]/[[groups_today]] (тикет 138), без единого
> «сброс-события». Триггер `on_reset_event_insert` удалён (тикет 137,
> `doc/db/remove_reset_events_trigger.sql`); таблица `reset_events` сама по
> себе **не удалена** (решение пользователя на ревью тикета 131 — сохранить
> историю, не чистить таблицу) и её RLS-антипаттерн (см.
> [[RLS-политики]]) остаётся неотозванным, но не входил в объём 137/138.
> Ниже — описание механизма как он работал до этих тикетов.

> Источник: `backup/database/schema.sql` (реальный `pg_dump`, тикет 111) —
> предыдущая версия этой заметки (по `doc/table_structure.md`, удалён в тикете 118) указывала
> `user_id smallint` и пропускала `children_count`; реально `user_id
> bigint` (как везде в проекте, FK на `users.id`) — см.
> `tickets/108/REVIEW_REPORT.md`, Critical 1.

Журнал операций массового сброса/открытия дня. Каждая вставка запускает
триггер `on_reset_event_insert`, который сразу пересчитывает
[[children_today]] и [[groups_today]] — сам по себе `reset_events` не
хранит агрегированных счётчиков по группам (кроме собственного
`children_count`, см. ниже), только историю событий (используется также
для отображения в `ResetHistoryPanel.vue`).

```sql
create table public.reset_events (
  id bigint generated by default as identity not null,
  created_at timestamp with time zone not null default now(),
  user_id bigint null,
  day character varying null,  -- date in ISO format yyyy-mm-dd
  children_count integer null default 0,
  event_type smallint null default '1'::smallint,
  constraint reset_events_pkey primary key (id)
);
```

- `children_count` — снимок числа детей на момент события; не читается
  триггером `on_reset_event_insert` (см. [[Триггеры]]) и не найден в
  `src/` как явно записываемое поле — назначение по имени столбца,
  фактический писатель не подтверждён в рамках этой ревизии.

## `event_type`

| Значение | Название | Что происходит |
|---|---|---|
| `0` | Total reset («Tag schließen») | `DELETE FROM children_today; DELETE FROM groups_today;` — полная очистка |
| `1` | Normal reset («Tag starten») | Первый reset дня: `groups_today.children_today = children_now`, затем `children_now = 0`; последующие resets того же дня — только `children_now = 0`. В обоих случаях `children_today.presence_now = 0` |
| `2` | Soft reset | Только `presence_now`/`children_now` обнуляются, без сохранения снимка |
