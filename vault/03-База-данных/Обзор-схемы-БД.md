> источник для этого раздела; `doc/table_structure.md` (удалён в тикете 118) / `doc/db_triggers.sql`
> / `doc/database_migration_config_rls.sql` / `doc/db/*.sql` — более старые
> ручные DDL-заметки, использовались только там, где не противоречат

> Critical 1) опиралась исключительно на `doc/table_structure.md` (удалён в тикете 118) и не
> учитывала уже доступный `schema.sql` — из-за этого расходилась с реальной
> схемой в нескольких таблицах; расхождения исправлены по итогам ревью.

Постоянного каталога `supabase/migrations/` в репозитории нет, но с тикета
111 есть `backup/database/schema.sql` — актуальный `pg_dump`, которым и
нужно руководствоваться в первую очередь. `doc/table_structure.md` (удалён в тикете 118) /
`doc/db_triggers.sql` / `doc/db/*.sql` — исторические ручные DDL-заметки
(применялись вручную через Supabase SQL Editor) и полезны как комментарий к
намерению миграции, но не как источник истины о текущих колонках/политиках.

## Находки реверс-инжиниринга

- Формулировка тикета 108.md упоминает таблицы `groups`, `buses` — **их не
  существует**. Группы и автобусы — не отдельные сущности, а просто
  smallint-поля (`children.group_id`, `scans.bus_id` и т.п.). Единственная
  агрегирующая по группам таблица — [[groups_today]]; число групп/автобусов
  хранится как значение в [[config]] (`total_groups`, `total_buses`). См.
  [[Группы-и-рабочий-день]], [[Учёт-автобусов]].
- В `schema.sql` есть целый слой таблиц (`sessions`, `invites`,
  `webauthn_challenges`, `auth.webauthn_credentials`) и Edge Function
  `supabase/functions/auth/index.ts`, реализующие альтернативную
  passkey/WebAuthn-аутентификацию с собственными JWT — **но, судя по grep
  по `src/`, эта ветка ни разу не вызывается из фронтенда** (используются
  только `invite-generate`/`invite-accept`/`delete-user`). См.
  [[Инвайты-сессии-WebAuthn]] — там же разбор, почему это выглядит как
  нерабочий/устаревший параллельный слой, а не часть боевого пути входа.

## Таблицы

| Таблица | Назначение |
|---|---|
| [[children]] | Справочник детей: имя, возраст, группа, привязанный браслет |
| [[scans]] | История всех сканирований браслетов (append-only) |
| [[children_today]] | Оперативное состояние присутствия ребёнка сегодня (upsert-таблица, источник истины для [[Переклички]]) |
| [[groups_today]] | Агрегированные счётчики присутствия по группам на сегодня |
| [[reset_events]] | Журнал операций сброса/открытия дня (0/1/2), запускает массовый пересчёт |
| [[users]] | Пользователи приложения (admin/user), связаны с `auth.users` |
| [[user_group_day]] | Ежедневная привязка Betreuer к группе/автобусу + статус присутствия |
| [[config]] | Общая конфигурация приложения (key/value) |
| [[days]] | Список дней мероприятия (расписание) |
| `admin_logs` | Лог административных действий (`admin_id`, `action`, `target_user_id`, `details jsonb`) — в коде `src/` не используется (ни SELECT, ни INSERT не найдены), назначение по DDL/комментарию `pg_dump` |
| `calendar` | `day`/`user_id`/`group_id`/`status`/`description` — используется в `src/views/DaysEditView.vue`; не описана отдельно в этой ревизии (обзорный уровень, за пределами таблиц из тикета 108) |
| `scan_type` | Справочник видов скана (`id smallint`, `name`) — вероятный источник значений для `scans.type`, отдельно не реверс-инжинирилась |
| [[Инвайты-сессии-WebAuthn]] | `invites`, `sessions`, `webauthn_challenges`, `auth.webauthn_credentials` — слой (частично неиспользуемый), связанный с приглашениями и альтернативной passkey-аутентификацией |
