# `scan_packets`

> Источник: `doc/db/scan_packets.sql`.

Заголовок пакета сканирования — реализация сущности **ScanPacket** (см.
[[Checkpoint]], глоссарий). Пакет — неизменяемый снимок: воспитатель
отправляет один пакет за один раз, сам пакет никогда не редактируется,
только целиком удаляется (`remove_checkpoint()`, см. [[checkpoints]]).
Сами дети пакета — не здесь, а в [[scans]] (`scans.packet_id` ссылается на
эту таблицу).

```sql
CREATE TABLE public.scan_packets (
  id bigint GENERATED BY DEFAULT AS IDENTITY NOT NULL,
  client_packet_id uuid NOT NULL,
  type smallint NOT NULL,               -- 1=BUS, 2=GROUP, 3=CHECKIN
  author_id bigint NOT NULL REFERENCES public.users(id),
  bus_id smallint NULL,
  group_id smallint NULL,
  date character varying NOT NULL,       -- формат scans.date/checkpoints.day
  started_at timestamptz NULL,
  finished_at timestamptz NOT NULL,
  received_at timestamptz NOT NULL DEFAULT now(),
  children_count smallint NOT NULL DEFAULT 0,
  cancelled_at timestamptz NULL,         -- зарезервировано, не используется
  CONSTRAINT scan_packets_pkey PRIMARY KEY (id),
  CONSTRAINT scan_packets_client_packet_id_key UNIQUE (client_packet_id),
  CONSTRAINT scan_packets_type_check CHECK (type IN (1, 2, 3)),
  CONSTRAINT scan_packets_bus_group_check CHECK (
    (type = 1 AND bus_id IS NOT NULL AND group_id IS NULL) OR
    (type = 2 AND group_id IS NOT NULL AND bus_id IS NULL) OR
    (type = 3 AND bus_id IS NULL AND group_id IS NULL)
  )
);

CREATE INDEX idx_scan_packets_bus_date ON public.scan_packets(bus_id, date) WHERE bus_id IS NOT NULL;
CREATE INDEX idx_scan_packets_group_date ON public.scan_packets(group_id, date) WHERE group_id IS NOT NULL;
```

`client_packet_id` (UUID, генерируется на клиенте) — якорь идемпотентности:
повторная отправка того же пакета (потеря ответа сети, повтор из офлайн-
очереди) не создаёт дубликат, `submit_scan_packet()` (см. [[checkpoints]])
делает `ON CONFLICT (client_packet_id) DO NOTHING` и возвращает уже
существующий `packet_id`. После `remove_checkpoint()` пакет удаляется
физически — `client_packet_id` освобождается, и повторная отправка того же
офлайн-пакета принимается как новый (осознанный риск, см. [[checkpoints]]).

`type` здесь — три значения (BUS/GROUP/**CHECKIN**), не то же самое, что
`checkpoints.type` (BUS/GROUP/**LAZY**): CHECKIN-пакет (тикет 136,
`ChildDetailView.vue` → «Präsenz registrieren») относится к типу LAZY на
уровне Checkpoint, но сам пакет не несёт ни `bus_id`, ни `group_id`
(констрейнт `scan_packets_bus_group_check`) — поэтому в модалке
`ChildPresenceModal.vue` выбор автобуса не сохраняется, это известное и
принятое следствие, не баг.

## RLS

`SELECT` — любой `authenticated` (`USING (true)`). Ни одной
`INSERT`/`UPDATE`/`DELETE`-политики для `authenticated` — запись только
через `submit_scan_packet()`, вызываемую Edge Function
`submit-scan-packet` под `service_role` (RLS не применяется). Не добавлять
«на всякий случай» разрешающую политику записи — см. [[RLS-политики]],
«Неотозванные широкие legacy-политики», почему этот паттерн уже обесценил
более узкие политики в других местах проекта.
